# AI 工作交接工作流

把当前会话中正在进行的工作转交给另一个 AI 会话或工具继续，要求上下文不丢失、权限不越界、接收方可自证理解、交接材料用后可清理。

## 输入与边界

开始前确认以下信息；缺少会实质影响产物时才询问用户：

- 交接的任务范围：全部上下文还是某个具体任务（默认：用户当前正在推进的任务）。
- 交接文档的目标位置：默认写入当前工作区的 `./.ai_tmp/`，用户指定其他路径时从其指定。
- 接收方类型与所在环境：影响启动提示词中对路径和工具的表述方式。

硬边界：

- **不得写入凭据、token、密码、私钥、内网敏感地址等秘密信息**；发现交接内容涉及秘密时停止并交由用户当面传递。
- 交接文档不是仓库交付物，不得提交到 git；写入前确认目标目录的忽略状态。
- 等待用户转述接收方提问期间，不继续改动被交接的工作，除非用户另行指示。

## 流程

### 1. 生成交接文档

写入 `<工作区>/.ai_tmp/交接-<任务标识>.md`。若该目录未被 git 忽略，同时把 `.ai_tmp/` 追加到本仓库的 `.git/info/exclude`（仅本地生效、不改仓库 `.gitignore`）。

文档结构按实际需要裁剪，不保留空章节：

1. **接收者须知**（置顶）：非仓库交付物、勿提交；读取并确认接手后删除本文件（附完整删除命令）；交接时间与仓库 HEAD。
2. **项目背景**：仓库根的绝对路径、当前分支与 HEAD、必读规则文件的绝对路径（按当前环境解析，不在技能中写死）。
3. **任务主线**：进行中任务的目标；已合入或已创建的 MR/commit 明细（hash + 链接 + 一句话内容）。
4. **关键文件与调用链**：核心文件、数据流或调用关系，用代码块示意。
5. **诊断结论或根因**（如适用）：供接收方复现与验证的事实链。
6. **当前状态**：代码、设备、环境各自的实际状态（含"已生效 / 需重新烧写或部署"等关键限定）。
7. **待办与验证清单**：写成可直接执行的命令形式。
8. **关键约束**：分支命名、MR 流程、授权边界、必须遵守的规则文件。
9. **已知坑**：曾踩过且接收方容易重复踩的问题。

### 2. 生成接收方启动提示词

产出一段用户可直接复制粘贴给接收方的文本，至少包含：

- **第一步（必读）**：交接文档的绝对路径；指示其完整阅读后按文档加载相关文件与约束。
- **第二步（理解确认）**：要求其先输出对任务状态的理解、文档中的歧义点、计划动作，**先不执行**，等用户确认。
- **疑问处理机制**：引用第 3 节的提问格式。
- **硬约束**：git 授权、MR 流程等（从交接文档第 8 节摘要）。
- **收尾**：确认接手完毕且无待澄清问题后删除交接文档。

### 3. 定义疑问中转机制

接收方对不确定信息不得自行假设或扩大范围，改为生成「提问提示词」交给用户，由用户转述给交接方或直接回答。格式：

```
【提问 N】<12 字内标题>
- 已确认事实：<已核实的信息，引用 file_path:line_number>
- 缺失信息：<需要知道什么>
- 影响：<不确认会导致的后果：范围 / 风险 / 返工>
- 建议选项：A) …  B) …  C) …
- 倾向建议：<推荐项 + 理由>
```

一次最多 4 条，按重要性排序。

### 4. 约定清理

- 接收方确认接手完毕后，按交接文档顶部「接收者须知」删除该文档。
- 若接收方仍需保留信息，应先把关键内容落到正式载体（`doc/`、MR 描述、问题单）再删除。
- 用户转述的问答如改变了任务结论，由用户决定是否回写交接文档或另行记录。

## 交付检查

生成后逐项自检：

- 交接文档与启动提示词中的路径真实可达，引用的 MR/commit/`file:line` 真实存在。
- 全文无凭据类敏感信息，无未替换的占位符。
- 待办条目可执行（命令可直接运行，或明确标注需用户操作的步骤）。
- 工作区 `git status` 不因交接文档出现新的未跟踪项（已加本地排除）。
- 接收方收到的是「文档路径 + 启动提示词」两件套，缺一不可。

## 停止条件

出现以下情况时停止并报告事实与所需决定，不得猜测继续：

- 交接范围或接收方环境不明，且推测会实质改变产物内容。
- 交接内容涉及凭据、密钥或敏感地址。
- 目标路径不可写，或写入会覆盖已有且来源不明的同名文档。
