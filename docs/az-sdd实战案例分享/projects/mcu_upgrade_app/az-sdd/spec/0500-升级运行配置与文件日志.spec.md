## Part 1：功能契约

### 用户目标与场景

部署人员无需重新构建程序即可通过 INI 文件调整升级包、网络、日志和 MCU/MPU 使能项。发生升级问题时，维护人员可从文件日志查看过程信息；没有配置文件时应用按默认参数继续运行。

### 用户流程

1. 可选地在设备配置目录放置升级配置文件。
2. 启动应用，系统加载可识别配置项或采用默认值。
3. 执行升级相关操作，系统把日志写入配置的目录并按容量维护文件。
4. 维护人员读取日志定位运行结果。

### 输入与输出

| 输入 | 规则 | 输出 |
|---|---|---|
| INI 文件 | 不存在或读取失败时采用默认值 | 实际运行配置 |
| 日志目录、标签、大小、数量 | 配置项覆盖默认值 | 日志文件集合 |
| MCU/MPU 使能项 | 关闭时对应目标不参与升级 | 升级执行范围 |

## Part 2：验收契约

## 验收标准

- [ ] [001] 不存在 INI 文件时，应用使用默认路径、默认升级包和默认日志参数启动。
- [ ] [002] INI 中有效的日志、升级包、网络和使能项会覆盖对应默认值。
- [ ] [003] 日志启用时，运行消息写入指定目录并可刷新、关闭。
- [ ] [004] 当日志达到配置上限时，系统按配置数量维护可用日志文件。
- [ ] [005] 禁用 MCU 或 MPU 后，整包升级不处理被禁用的目标。

## 测试用例

### MT001 默认配置
- **测试步骤**：移除配置文件后启动应用。
- **预期结果**：应用成功启动且使用默认值。
- **验收标准**：[001]

### MT002 覆盖配置和日志
- **测试步骤**：设置自定义日志目录、文件大小和升级包路径，启动并产生日志。
- **预期结果**：日志在指定位置生成，运行使用指定包路径。
- **验收标准**：[002][003][004]

### MT003 目标使能
- **测试步骤**：分别关闭 MCU、MPU 使能项并执行完整包升级。
- **预期结果**：被关闭目标不会进入升级步骤。
- **验收标准**：[005]
