## Part 1：功能契约

### 用户目标与场景

维护人员在升级开始前需要确认 MCU 升级文件与安全升级包未损坏、目标硬件匹配，且安全包可使用受控密钥正确解出所需升级文件。无效包不得进入升级传输或刷写。

### 用户流程

1. 提供普通 MCU 文件或安全升级包及其密钥材料。
2. 系统读取包头、目标信息和完整性摘要。
3. 对安全包验证并解出所需文件。
4. 校验通过的文件交给后续升级；任一步失败则报告失败。

### 输入与输出

| 输入 | 规则 | 输出 |
|---|---|---|
| 普通升级文件 | 头部、长度、摘要和目标信息有效 | 可读的升级项 |
| 安全升级包 | 需要密钥、初始向量和签名公钥 | 解出的升级文件 |
| 目标硬件版本 | 应与包声明匹配 | 接受或拒绝 |

## Part 2：验收契约

## 验收标准

- [ ] [001] 普通 MCU 文件仅在头部、长度和 MD5 校验通过时可读取升级项。
- [ ] [002] 文件目标硬件信息不匹配时，系统拒绝该升级文件。
- [ ] [003] 安全升级包仅在需要的密钥材料可用且解包过程完整时生成目标文件。
- [ ] [004] 摘要、头部、签名或解包失败时，系统不向后续升级提供有效数据。
- [ ] [005] 校验通过时，可按升级项和偏移量读取数据，供 MCU 升级传输使用。

## 测试用例

### MT001 正常 MCU 文件
- **测试步骤**：提供匹配硬件的有效 MCU 文件并执行校验和读取。
- **预期结果**：校验成功并可读取全部升级项。
- **验收标准**：[001][005]

### MT002 损坏或不匹配文件
- **测试步骤**：分别篡改摘要、头部和硬件版本。
- **预期结果**：每种文件均被拒绝。
- **验收标准**：[002][004]

### MT003 安全包解包
- **测试步骤**：提供有效安全包和密钥材料，再移除其中任一材料重试。
- **预期结果**：材料齐全时解包成功；缺失或无效时失败。
- **验收标准**：[003][004]
