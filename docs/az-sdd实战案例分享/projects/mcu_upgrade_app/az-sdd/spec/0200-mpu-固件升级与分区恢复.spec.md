## Part 1：功能契约

### 用户目标与场景

维护人员为受支持的 MPU 平台（包括 N725A）指定升级镜像，执行升级、备份或回滚，并在整个过程中获得状态与进度。系统在重启后确认升级结果；必要时先备份可用分区。对于厂商未提供但上层流程要求存在的辅助能力，平台可采用兼容成功策略，保证统一升级流程能够继续执行。

### 用户流程

1. 初始化与平台匹配的升级能力，设置镜像路径。
2. 查询当前分区信息；按需请求升级、备份或回滚。
3. 循环处理升级状态并读取进度回调。
4. 升级完成后等待重启和确认，得到成功或失败结论。
5. N725A 使用模组整包 FOTA 能力升级非活动系统，重启后由模组完成 A/B 系统同步。

### 输入与输出

| 输入 | 规则 | 输出 |
|---|---|---|
| 镜像路径 | 非空且长度合法 | 接受或路径错误 |
| 操作类型 | 升级、备份、回滚 | 操作受理或状态错误 |
| 超时时间 | 合法值使用；异常值使用默认时限 | 完成或超时 |
| 状态/分区查询 | 平台支持时可调用 | 当前状态、进度、A/B 分区信息 |
| N725A 辅助操作 | 厂商未提供且不影响升级正确性的操作可兼容成功 | 流程继续执行；不得伪造关键分区数据 |

## Part 2：验收契约

## 验收标准

- [ ] [001] 支持的平台可完成初始化并显示空闲、升级中、等待重启、等待确认、成功或失败状态。
- [ ] [002] 空路径、过长路径或非空闲状态下发起操作时，系统返回明确失败结果。
- [ ] [003] 升级过程报告 0–100 进度；错误时报告负错误结果。
- [ ] [004] 平台需要时，升级会先完成备份，再进入刷写。
- [ ] [005] 重启后的确认成功才形成升级成功；确认超时或失败时形成失败。
- [ ] [006] 支持的平台可查询活动分区及另一分区是否损坏。
- [x] [007] N725A 使用有效整包发起升级后，系统进入升级中并在厂商调用成功时报告 100% 与等待重启。（自动化测试通过）
- [x] [008] N725A 缺少主动备份、回滚接口时，兼容操作直接成功且不阻塞 NF 整包升级流程。（自动化测试通过）
- [x] [009] N725A 升级路径为空、过长、文件不存在或厂商升级调用失败时，系统进入失败状态并报告负错误结果。（自动化测试通过）
- [ ] [010] N725A 重启进入新系统后，MPU 确认成功并允许 NF 流程继续；原有平台行为保持不变。（待设备验收）

## 测试用例

### MT001 MPU 升级
- **测试步骤**：在目标平台设置有效镜像，发起升级并持续读取状态。
- **预期结果**：获得递增进度，重启确认后为成功。
- **验收标准**：[001][003][005]

### MT002 异常输入
- **测试步骤**：以空路径、超长路径及升级中重复请求执行操作。
- **预期结果**：每次均被拒绝且保留可查询状态。
- **验收标准**：[002]

### MT003 分区恢复
- **测试步骤**：在支持的平台查询分区并执行备份或回滚。
- **预期结果**：返回分区信息，操作过程产生状态与回调。
- **验收标准**：[004][006]

### MT004 N725A 整包升级与兼容接口
- **测试步骤**：在 N725A 设备设置有效整包，发起升级并轮询状态；重启后继续查询；分别调用兼容备份和回滚操作。
- **预期结果**：升级调用成功后进度达到 100% 并等待重启；重启后确认成功；兼容操作直接成功且不改变关键分区数据。
- **验收标准**：[007][008][010]

### MT005 N725A 异常输入
- **测试步骤**：依次使用空路径、超长路径、不存在文件及可触发厂商调用失败的包执行升级。
- **预期结果**：各场景均返回失败并保留可查询的失败状态和错误结果。
- **验收标准**：[009]
