## Part 1：功能契约

### 用户目标与场景

运维人员在设备上准备完整升级包后，发起一次 NF 升级；系统根据包内目标执行 MPU 和/或 MCU 升级，在重启后确认结果，并提供进度、状态与失败原因。掉电重启后，系统恢复未完成任务并继续确认。

### 用户流程

1. 提供新的请求标识并发起升级。
2. 系统预检查升级包与所需升级目标。
3. 依次完成 MPU、MCU 升级；无对应内容的目标跳过。
4. 系统等待设备重启，随后确认 MPU 与 MCU 的最终结果。
5. 用户查询任务状态、百分比和错误码；成功或失败后可再次发起新任务。

### 输入与输出

| 输入 | 规则 | 输出 |
|---|---|---|
| 升级请求 ID | 仅空闲、成功或失败状态接受新 ID | 当前任务 ID |
| 本地完整升级包 | 必须可读取且通过预检查 | 是否进入升级流程 |
| 状态查询 | 查询当前任务 | 状态、0–100 进度、错误码 |
| 取消请求 | 仅对进行中任务生效 | 任务进入失败状态 |

## Part 2：验收契约

## 验收标准

- [ ] [001] 空闲状态提交新请求后，系统进入预检查并返回对应任务 ID。
- [ ] [002] 包中仅包含 MPU 或仅包含 MCU 内容时，系统只执行相应升级步骤。
- [ ] [003] 包校验失败时，系统不进入刷写步骤，并报告无效升级包错误。
- [ ] [004] 升级中查询可得到当前状态、进度和错误码。
- [ ] [005] 升级后的重启确认完成时，系统报告成功；任一升级或确认失败时报告失败。
- [ ] [006] 在等待重启阶段掉电后重新启动，系统恢复任务并进入对应确认步骤。

## 测试用例

### MT001 完整升级流程
- **测试步骤**：准备包含 MPU 与 MCU 内容的有效完整升级包，发起请求并轮询状态。
- **预期结果**：依次出现预检查、MPU、MCU、等待重启、确认和成功状态。
- **验收标准**：[001][004][005]

### MT002 无效包拦截
- **测试步骤**：提供损坏或不匹配的完整升级包并发起请求。
- **预期结果**：任务失败，且未执行刷写。
- **验收标准**：[003]

### MT003 掉电恢复
- **测试步骤**：在等待重启时断电并重启应用。
- **预期结果**：应用恢复保存的升级标记并继续确认。
- **验收标准**：[006]
