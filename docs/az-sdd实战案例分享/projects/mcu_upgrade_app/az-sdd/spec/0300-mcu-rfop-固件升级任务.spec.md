## Part 1：功能契约

### 用户目标与场景

维护人员提供 MCU 升级文件和任务 ID 后，可启动、查看或取消一项 MCU 升级任务；系统会校验文件、传输升级数据并通过状态属性反馈任务结果。

### 用户流程

1. 启动 RFOP 服务并准备升级文件。
2. 提供文件名与任务 ID，开始 MCU 升级。
3. 查询当前任务 ID、状态、百分比和结果。
4. 必要时取消当前任务；完成后读取最终结果。

### 输入与输出

| 输入 | 规则 | 输出 |
|---|---|---|
| 升级文件名 | 文件必须可打开并通过头部/摘要校验 | 可启动或失败 |
| 任务 ID | 用于识别当前任务 | 当前任务 ID |
| 取消 ID | 应匹配当前任务 | 已取消或拒绝 |
| 状态查询 | 查询当前执行任务 | 状态、百分比、结果 |

## Part 2：验收契约

## 验收标准

- [ ] [001] 有效 MCU 升级文件和任务 ID 可创建升级任务。
- [ ] [002] 系统对外持续报告当前任务 ID、状态、百分比及最终结果。
- [ ] [003] 文件无法打开、头部不匹配或摘要不匹配时，任务不开始传输并报告失败。
- [ ] [004] 取消当前有效任务后，系统停止该任务并给出最终失败/取消结果。
- [ ] [005] MCU 升级完成后，整包升级可继续等待重启并执行 MCU 确认。

## 测试用例

### MT001 MCU 任务执行
- **测试步骤**：启动服务，提交有效升级文件及任务 ID，持续查询状态。
- **预期结果**：任务从开始进入完成，百分比与结果可读。
- **验收标准**：[001][002]

### MT002 文件校验失败
- **测试步骤**：提交头部或摘要损坏的 MCU 文件。
- **预期结果**：任务失败且不发送有效升级数据。
- **验收标准**：[003]

### MT003 取消任务
- **测试步骤**：在传输中提交当前任务的取消请求。
- **预期结果**：任务被停止并公开最终结果。
- **验收标准**：[004]
