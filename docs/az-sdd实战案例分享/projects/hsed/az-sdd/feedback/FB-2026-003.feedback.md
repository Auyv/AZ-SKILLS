## 原始描述

> 操作系统相关接口需要优先使用 sfc组件接口，这是公司的接口规范。

## 问题场景

当前公司自有实现中仍存在直接使用操作系统接口的情况：

1. `framework/bsc_hse/common/bsc_hse.c` 使用 `pthread_mutex_t`、
   `pthread_mutex_lock` 和 `pthread_mutex_unlock` 实现组件级互斥。
2. `common/main.c` 使用 `signal` 注册进程退出信号。
3. `rte_component/rte_hse/src/rte_hse.c` 使用 `dlopen`、`dlsym` 和
   `dlclose` 实现 Linux 动态库适配。

项目 SFC 已提供 `TSfCriticalSection`，可覆盖 BSC 的进程内互斥场景，因此
BSC 直接使用 pthread 不符合“存在 SFC 等价能力时优先使用 SFC”的公司规范。
当前已检查的 SFC 头文件未提供 POSIX 信号和动态库加载等价接口，这两类接口不能
机械替换，需要限制在明确的平台边界并登记例外。

## 期望行为

1. 公司自有业务层、组件层和框架层在 SFC 已提供等价能力时，必须优先使用 SFC。
2. BSC HSE 的组件级互斥由 `TSfCriticalSection` 实现，不再直接依赖 pthread。
3. SFC 对象的创建、使用、销毁顺序明确，禁止在临界区未创建时注册 vendor 或调用
   BSC 公共接口。
4. 只有 SFC 未提供等价能力时才允许直接使用 OS 接口，并且必须限制在进程入口、
   RTE 平台适配或供应商 SDK 平台端口等明确边界。
5. 新增静态检查，防止公司自有非平台代码重新引入可由 SFC 替代的 OS 接口。

## 影响分析

- BSC 当前使用静态 `PTHREAD_MUTEX_INITIALIZER`，而 `TSfCriticalSection` 必须显式
  调用 `TSfCriticalSectionCreate` 并通过 `OfDestroyObject` 销毁。
- `RteHseInit` 当前在 `BscHseInit` 前调用 `BscHseVendorRegister`，注册函数已经需要
  获取 BSC 全局锁；直接替换锁类型会产生“锁尚未创建便被使用”的生命周期缺陷。
- 修复需要增加 BSC 运行时基础设施的显式初始化/反初始化契约，并同步调整 RTE、
  app 初始化回滚以及 fake/RTE 测试顺序。
- `signal` 和 `dlopen/dlsym/dlclose` 在当前 SFC 中未找到等价接口，保留它们不代表
  普遍豁免，只作为受控的平台接口例外。
- 该变化涉及 BSC/RTE 生命周期和公共依赖契约，属于高风险架构修订，编码前必须
  完成人工审核。

## 待审核技术决策

1. 在 BSC vendor 契约中增加 `BscHseRuntimeInit` 和
   `BscHseRuntimeDone`，只负责创建/销毁 `TSfCriticalSection` 及维护 runtime
   基础状态，不连接硬件。
2. 生命周期固定为：
   `BscHseRuntimeInit -> RTE 加载并注册 vendor -> BscHseInit -> 运行`；
   退出严格逆序执行。
3. `RteHseInit` 负责在注册 vendor 前建立 BSC runtime；任何加载或注册失败均回滚
   runtime。`RteHseDone` 在解除注册并卸载动态库后销毁 runtime。
4. BSC 功能 API 在线程并发前必须处于 runtime ready 状态；runtime 引导和销毁阶段
   由 app 主线程串行执行。
5. `signal` 作为进程入口例外保留，`dlopen/dlsym/dlclose` 作为 Linux RTE 例外保留；
   供应商 SDK 的系统调用只允许存在于其平台端口目录。

## 验证方式

1. 扫描 `framework/bsc_hse`，确认不再包含 `pthread.h`、
   `pthread_mutex_*` 或 `PTHREAD_MUTEX_INITIALIZER`。
2. 验证 `TSfCriticalSectionCreate`、`Enter/Leave` 和
   `OfDestroyObject` 生命周期完整且失败路径可回滚。
3. 覆盖 runtime 未初始化、重复初始化、注册失败、BSC 初始化失败、正常退出和重复
   退出测试。
4. 运行 BSC 全量主机回归和 RTE 加载器异常路径测试。
5. 执行 AG35 CETDA 交叉构建。
6. 扫描公司自有代码中的直接 OS 接口，确认每一处均已迁移或属于规范定义的例外。

## 经验沉淀

- SFC 临界区必须显式构造，不能把 `PTHREAD_MUTEX_INITIALIZER` 机械替换为零初始化。
- vendor 注册发生在 BSC 硬件初始化之前，因此锁生命周期必须独立于
  `BscHseInit/BscHseDone`。
- SFC 不提供等价接口时，直接 OS 调用必须限制在 app 入口、RTE 平台层或供应商
  SDK 边界，并通过静态扫描防止扩散。
