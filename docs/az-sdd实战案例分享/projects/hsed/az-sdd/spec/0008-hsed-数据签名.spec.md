## Part 1：功能契约

### 用户目标

HSED 调用方能够使用硬件私钥槽位对完整原文或调用方提供的摘要进行签名，获得格式和分量长度明确的签名结果；SM2 签名自动使用当前对象 `USER_ID` 的前 16 字节派生 ZA。

### 使用场景

1. 使用 RSA1024、RSA2048、ECC256、SM2 或 SM9 的私钥槽位签名业务数据。
2. 选择原文模式，由芯片按配置摘要算法完成摘要和签名。
3. 选择摘要模式，提交长度与所选摘要算法严格匹配的预计算摘要。
4. 多业务进程并发签名，由 HSED 保护对象身份上下文和芯片串行访问。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | 有效对象、非对称 `HsedAlgorithm`、完整原文或摘要、签名输入模式 |
| 密钥 | 对应算法的 `PRIVATE_KEY_ID` |
| 摘要配置 | 对应算法的 `HASH_ALGORITHM`；摘要模式时输入长度必须匹配 |
| SM2 身份 | 当前对象已设置且长度不少于 16 字节的 `USER_ID`；只使用前 16 字节作为 ZA 身份输入，ZA 不由上层传入 |
| 输出 | 签名字节、实际长度，以及适用时的 `r_size`、`s_size` |

### 业务规则

- 只允许当前物料声明支持的 RSA1024、RSA2048、ECC256、SM2 或 SM9 签名；对称或哈希算法作为签名主算法时返回 `UNSUPPORTED`。
- 签名只能使用私钥槽位；公钥槽位、算法不匹配槽位或不存在槽位必须被拒绝。
- 原文模式使用完整输入并按当前 `HASH_ALGORITHM` 处理；摘要模式不得再次摘要，且输入长度必须严格匹配所选摘要算法。
- SM2 签名前必须存在长度不少于 16 字节的 `USER_ID`。HSED 只使用前 16 字节与当前 SM2 公钥派生 ZA；上层无需传入 ZA。
- CIU98 适配层必须按当前对象配置的 `SM2_PUBLIC_KEY_ID` 调用 `api_export_public_key()`，将导出的 64 字节 SM2 公钥值和 `USER_ID[0..15]` 传给 `api_sm2_get_za()`；不得从私钥槽位隐式推导公钥槽位，也不得将 16 字节身份输入直接当作 ZA。
- SM2 原文模式必须按 `ZA || M` 语义执行 SM2+SM3 签名。当前 CIU98 物料不支持保持该语义的调用方摘要模式，因此 SM2 摘要模式返回 `UNSUPPORTED`。
- 缺失或长度小于 16 字节的 `USER_ID` 返回 `INVALID_PARAM`；长度大于 16 字节时忽略第 17 字节及之后内容，不得用 `CHIP_ID`、槽位、会话或默认字符串替代。
- ECC256 和 SM2 签名按 `r || s` 顺序返回，且 `r_size + s_size` 等于签名实际长度；RSA 和不采用该格式的算法返回 `r_size=0`、`s_size=0`。
- 输入和输出按二进制长度处理，输出容量不足返回 `DATA_TOO_LARGE`，不得截断签名。
- 物料不支持的算法、摘要或模式返回 `UNSUPPORTED`，不得软件签名或更换算法。
- 多线程签名必须保护同一对象的 `USER_ID`、摘要属性、公钥槽位和私钥槽位，芯片调用保持串行；不同连接或对象的 ZA 临时数据不得串线。

### 使用流程

1. 调用方创建对象，配置私钥槽位、摘要算法和输入模式。
2. SM2 签名时先设置不少于 16 字节的 `USER_ID`；签名身份固定取前 16 字节。
3. 调用方提交主算法及原文或摘要。
4. HSED 校验对象、槽位、属性、身份上下文、输入长度和输出容量。
5. CIU98 先计算 ZA，再对 `ZA || M` 完成签名并返回签名字节及分量长度；失败时不返回部分签名。

### 特殊情况

- 未设置或长度小于 16 字节的 SM2 `USER_ID`：返回 `INVALID_PARAM`；长度大于 16 字节时只截取前 16 字节。
- 摘要模式输入长度错误：返回 `INVALID_PARAM`。
- 使用公钥槽位签名：返回 `INVALID_PARAM` 或 `PERMISSION_DENIED`。
- 输出容量不足：返回 `DATA_TOO_LARGE`。
- `api_export_public_key()` 失败、导出公钥长度不是 64 字节、`api_sm2_get_za()` 失败或当前 SM2 公私钥槽位不匹配：签名失败且不返回部分签名。
- SM2 摘要模式：当前 CIU98 物料返回 `UNSUPPORTED`，不得绕过 ZA 身份语义。
- 验签不属于当前功能范围，不因本规范新增。

## Part 2：验收契约

### 验收标准

- [ ] [001] 每种当前物料声明支持的签名算法均可使用对应私钥槽位产生可由标准或供应商工具验证的签名。
- [ ] [002] 公钥槽位、错误算法槽位和不存在槽位均不能用于签名。
- [ ] [003] 原文模式与摘要模式按各自语义处理；摘要模式输入长度不匹配时返回 `INVALID_PARAM`。
- [ ] [004] SM2 使用当前对象 `USER_ID` 的前 16 字节派生 ZA，上层无需传入 ZA。
- [ ] [005] SM2 缺失或长度小于 16 字节 `USER_ID` 时返回 `INVALID_PARAM`；长度大于 16 字节时只使用前 16 字节，也不使用其他标识替代。
- [ ] [006] ECC256/SM2 签名满足 `r_size+s_size=签名长度`；其他非分量格式返回两个长度为 0。
- [ ] [007] 输出容量不足返回 `DATA_TOO_LARGE`，不返回截断签名。
- [ ] [008] 不支持的算法、摘要或模式返回 `UNSUPPORTED`，不软件回退。
- [ ] [009] 多线程并发签名时身份、属性、私钥和响应不串线，芯片调用保持串行。
- [ ] [010] CIU98 按当前对象 SM2 公钥槽位调用 `api_export_public_key()`，将导出的 64 字节公钥值和 `USER_ID[0..15]` 传给 `api_sm2_get_za()`，并对 `ZA || M` 完成签名。
- [ ] [011] 多通道使用不同随机 16 字节 `USER_ID` 对相同数据签名时，各签名仅能用对应身份上下文验证，跨通道交叉验证失败。
- [ ] [012] SM2 摘要模式返回 `UNSUPPORTED`；ZA 计算或密钥匹配失败时不返回部分签名。

### 测试用例

#### MT001 各算法签名与外部验证
- **测试步骤**：使用各受支持算法和合法私钥槽位签名固定消息，以标准或供应商工具验证。
- **预期结果**：签名验证通过。
- **验收标准**：[001]

#### MT002 槽位与模式校验
- **测试步骤**：分别使用公钥槽位、错算法槽位、原文模式和合法/非法长度摘要模式签名。
- **预期结果**：合法模式成功；非法槽位或摘要长度明确失败。
- **验收标准**：[002] [003]

#### MT003 SM2 USER_ID 与 ZA
- **测试步骤**：分别设置 16 字节、15 字节和大于 16 字节的 `USER_ID` 完成签名测试；对超长值分别使用前 16 字节和完整值做外部验证；再测试未设置 USER_ID 的对象。
- **预期结果**：16 字节及超长值可签名，超长值只与前 16 字节身份上下文匹配；未设置、15 字节和替代标识均返回 `INVALID_PARAM` 且无签名。
- **验收标准**：[004] [005]

#### MT004 签名格式与容量
- **测试步骤**：检查 ECC256/SM2 的 `r`、`s` 分量；检查 RSA/SM9 分量长度；再使用不足输出容量。
- **预期结果**：分量关系符合规则；容量不足返回 `DATA_TOO_LARGE` 且不截断。
- **验收标准**：[006] [007]

#### MT005 能力、并发与接口性能
- **测试步骤**：请求物料不支持的签名组合；在单进程中启动至少 8 个线程，每个线程建立独立 SPC 连接和对象，使用固定 SM2 公私钥槽位及各自随机生成的 16 字节 `USER_ID` 对完全相同的原始消息多次签名，并逐次记录签名接口调用耗时。
- **预期结果**：不支持组合返回 `UNSUPPORTED`；并发响应、对象身份和 ZA 临时数据不串线，芯片调用串行；日志可按通道、轮次追溯每次调用耗时。
- **验收标准**：[008] [009] [010]

#### MT006 多通道 ZA 交叉验证
- **测试步骤**：对 MT005 产生的每个签名，使用本通道 `USER_ID` 和公钥做正向验证，再使用其他所有通道的 `USER_ID` 做交叉验证；验证过程不计入签名接口耗时。
- **预期结果**：对应身份验证通过，所有跨通道身份验证失败。签名字节是否相同不作为身份隔离判据，因为 SM2 签名可使用随机数。
- **验收标准**：[011]

#### MT007 ZA 失败和 SM2 摘要模式
- **测试步骤**：模拟 `api_export_public_key()` 失败、导出公钥长度错误、`api_sm2_get_za()` 失败、公私钥槽位不匹配，并请求 SM2 摘要模式签名。
- **预期结果**：前两种情况不继续签名且无部分输出；摘要模式返回 `UNSUPPORTED`。
- **验收标准**：[012]

## Part 3：非功能需求与实现影响提示

### 非功能需求

| 类型 | 用户可感知要求 | 验收方式 |
|---|---|---|
| 互操作性 | 签名可由约定的外部工具验证 | MT001、MT003 |
| 身份安全 | SM2 缺失身份上下文时不签名 | MT003 |
| 格式稳定 | 签名和分量长度含义明确 | MT004 |
| 并发安全 | 多线程身份与签名结果不串线 | MT005 |
| 身份隔离 | 不同通道的 `USER_ID` 形成独立 ZA 身份上下文 | MT006 |
| 性能可观测性 | 逐次记录签名接口调用耗时，计时覆盖 HSED 内部 ZA 计算与签名，不包含外部验签 | MT005 日志 |

### 实现影响提示

| 类型 | 说明 |
|---|---|
| 既有规范 | 继承 0002 的“至少 16 字节、只取前 16 字节” `USER_ID` 与 ZA 保护规则 |
| CIU98 参数 | 适配层签名参数需要同时获得当前对象 SM2 公钥槽位、私钥槽位与 `USER_ID[0..15]`，先调用 `api_export_public_key()` 获得 64 字节公钥，再调用 `api_sm2_get_za()` 并签署 `ZA || M` |
| 模式限制 | 当前 CIU98 物料下 SM2 摘要模式返回 `UNSUPPORTED` |
| 权威模型 | 算法、属性和输出语义以 `doc/hsed.xlsx` 为准 |
| 父级约束 | 继承 0004 的 SDK 隔离、多线程安全和物料能力规则 |
