## Part 1：功能契约

### 用户目标

系统集成人员可以在受控初始化流程中确认固定槽位 1～14 均具备匹配算法和角色的密钥，并对安全允许的缺失项进行补齐。

### 业务规则

- 补齐范围覆盖对称槽位 1～4、四类现有非对称密钥对槽位 5～12 和 SM9 槽位 13/14。
- 只有明确确认槽位为空时才允许补齐；通信、认证、算法不匹配或未知状态不能按“空槽”处理。
- 生产模式不得自动覆盖已有密钥。
- 对称密钥和 SM9 的生成或安全注入必须具备明确的密钥来源、权限和审计约束；不得用临时固定值代替。
- 全部必需槽位检查通过后才可将设备报告为完整就绪。
- 当前一期仅实现 RSA1024、RSA2048、ECC256、SM2 的启动校验及受控调试修复；对称密钥和 SM9 自动补齐未实现。

## Part 2：验收契约

### 验收标准

- [ ] [001] 可准确区分空槽、正确密钥、算法错误、角色错误和不可查询状态。
- [ ] [002] 对称密钥与 SM9 使用经批准的安全生成或注入流程完成补齐。
- [ ] [003] 生产模式不覆盖已有密钥，任何失败不产生半套密钥对。
- [ ] [004] 补齐后重新检查 1～14，全部算法和角色满足固定映射。

### 测试用例

#### MT001 全量空槽补齐
- **测试步骤**：在受控测试设备上分别构造缺失的对称、非对称和 SM9 槽位，执行补齐并复查。
- **预期结果**：只补齐明确为空且允许处理的槽位；复查全部通过。
- **验收标准**：[001] [002] [004]

#### MT002 异常状态保护
- **测试步骤**：构造通信失败、算法错误、角色错误、已有密钥和中途失败。
- **预期结果**：不把异常当作空槽，不在生产模式覆盖，不留下可被报告为成功的半完成状态。
- **验收标准**：[001] [003]
