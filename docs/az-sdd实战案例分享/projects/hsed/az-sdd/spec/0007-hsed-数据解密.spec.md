## Part 1：功能契约

### 用户目标

HSED 调用方能够使用与密文匹配的算法、硬件密钥槽位和属性组完成解密，获得完整二进制明文；错误密文、错误密钥或不受支持能力必须明确失败，不得输出看似有效的部分明文。

### 使用场景

1. 使用 AES128、TDES128、SM1 或 SM4 对称密钥槽位解密业务密文。
2. 使用当前物料支持的 RSA1024、RSA2048、ECC256、SM2 或 SM9 私钥槽位解密密文。
3. 多个业务进程并发请求解密，由 HSED 安全串行访问同一加密芯片。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | 有效对象、`HsedAlgorithm`、完整二进制密文及其长度 |
| 对称配置 | 对应算法的 `KEY_ID`、模式、补位和按需设置的 IV |
| 非对称配置 | 对应算法的 `PRIVATE_KEY_ID` 及算法要求的补位或模式 |
| 输出 | 完整明文和实际长度，或统一失败结果 |

### 业务规则

- 每次解密必须显式指定算法，只读取与该算法完全匹配的属性组。
- 对称解密固定选择对应对称槽位；非对称解密固定选择对应私钥槽位，调用方不能改用公钥槽位。
- 模式、补位和 IV 必须与产生密文时的配置一致；缺失或非法组合返回 `INVALID_PARAM`。
- 密文和明文按完整二进制长度处理，可包含 `0x00`。
- 补位校验失败、密文格式错误或完整性不满足算法要求时必须失败，不得返回部分明文。
- 输入/输出超过 SPC、算法或物料限制时返回 `DATA_TOO_LARGE`，不得截断。
- 当前物料不支持的算法、模式或补位返回 `UNSUPPORTED`，不得软件回退。
- 多线程解密安全，实际 SDK/芯片操作串行，任何请求不得读取其他对象的属性或结果。

### 使用流程

1. 调用方创建对象，使用对象自带的固定密钥槽位并配置与密文一致的可写算法属性。
2. 调用方提交算法和完整密文。
3. HSED 校验对象、槽位角色、属性、密文长度和输出容量。
4. 芯片完成解密后返回完整明文；任一校验或芯片步骤失败时不返回部分明文。

### 特殊情况

- 密钥槽位不存在：返回 `KEY_NOT_FOUND`。
- 尝试修改固定私钥槽位：返回 `PERMISSION_DENIED`，解密仍使用原固定槽位。
- 密文长度、格式或补位非法：返回 `INVALID_PARAM` 或 `DEVICE_ERROR`，输出为空。
- 输出容量不足：返回 `DATA_TOO_LARGE` 并报告所需长度。
- 芯片忙、超时或断开：返回对应统一错误。

## Part 2：验收契约

### 验收标准

- [ ] [001] 每种当前物料声明支持的对称算法均可解密对应合法密文并恢复完整明文。
- [ ] [002] 每种当前物料声明支持的非对称解密算法均只使用对应私钥槽位。
- [ ] [003] 含 `0x00` 的明文经加密后再解密可逐字节完整恢复。
- [ ] [004] 错误算法或属性组被明确拒绝；固定私钥槽位不能被调用方修改。
- [ ] [005] 错误密文、错误补位或错误 IV 不返回部分明文或伪成功。
- [ ] [006] 输入或输出超限返回 `DATA_TOO_LARGE`，不截断。
- [ ] [007] 不支持的算法、模式或补位返回 `UNSUPPORTED`，不软件回退。
- [ ] [008] 多线程并发解密时结果与请求一一对应，芯片调用保持串行。
- [ ] [009] 忙、超时、设备断开和未知 SDK 错误映射为稳定统一结果。

### 测试用例

#### MT001 对称往返验证
- **测试步骤**：使用各受支持对称算法加密包含 `0x00` 的明文，再以相同属性解密。
- **预期结果**：逐字节恢复原始明文。
- **验收标准**：[001] [003]

#### MT002 非对称私钥解密
- **测试步骤**：使用对应固定公钥槽位加密合法明文，再使用固定私钥槽位解密。
- **预期结果**：恢复原文；解密只使用私钥槽位。
- **验收标准**：[002]

#### MT003 错误配置与错误密文
- **测试步骤**：分别使用空输入、错误算法、错误 IV、损坏密文和错误补位解密，并尝试修改固定私钥槽位。
- **预期结果**：所有非法请求失败且不返回部分明文；槽位修改返回 `PERMISSION_DENIED`。
- **验收标准**：[004] [005]

#### MT004 容量与能力边界
- **测试步骤**：提交超限密文、不足输出容量和物料不支持的算法。
- **预期结果**：分别返回 `DATA_TOO_LARGE` 或 `UNSUPPORTED`，不截断、不回退。
- **验收标准**：[006] [007]

#### MT005 并发与故障映射
- **测试步骤**：至少 8 个线程并发解密不同密文，并注入忙、超时、断开及未知错误。
- **预期结果**：结果不串线、芯片调用串行；错误结果稳定。
- **验收标准**：[008] [009]
