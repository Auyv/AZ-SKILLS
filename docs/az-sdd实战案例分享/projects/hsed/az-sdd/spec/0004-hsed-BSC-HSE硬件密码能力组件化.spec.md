## Part 1：功能契约

### 用户目标

HSED 服务开发者可通过独立的 BSC HSE 组件使用硬件密码能力，使 SPC 上层服务不直接依赖供应商 SDK。更换运营商或硬件平台的 SDK 时，应在不改变 HSED 对外 SPC 功能契约的前提下完成适配，并保持统一的算法、属性、密钥槽位和错误语义。

### 使用场景

1. HSED SPC 服务处理对象管理、属性读写和密码业务请求时，通过统一的 BSC HSE 能力完成具体操作。
2. 项目切换运营商、硬件平台或供应商 SDK 时，集成人员替换或新增对应适配，而不修改 SPC 对外接口及上层业务流程。
3. 供应商 SDK 返回专用状态、错误码或不支持某项能力时，HSED 调用方仍获得统一、可辨识的 HSED 结果。
4. 多个 SPC 客户端同时发起请求时，HSED 继续以受控方式访问同一硬件加密设备，避免供应商 SDK 状态或硬件通信过程相互干扰。

### 功能范围

本功能承载 `doc/hsed.xlsx` 当前定义的 11 项 HSED 能力：

| 类别 | 能力 |
|---|---|
| 对象管理 | HseCreate、HseDestroy |
| 属性管理 | SetPropertyInt、SetPropertyBytes、GetPropertyInt、GetPropertyBytes |
| 密码运算 | Encrypt、Decrypt、Sign |
| 公钥管理 | ExportPublicKey；ImportPublicKey 为兼容保留入口并执行固定槽位拒绝策略 |

### 输入与输出

| 项目 | 内容 |
|---|---|
| 调用来源 | HSED SPC 上层服务发起的对象管理、属性管理、密码运算和公钥管理请求 |
| 输入语义 | 沿用 `doc/hsed.xlsx` 定义的对象、算法、属性、密钥槽位、二进制数据、覆盖控制和缓冲区容量语义 |
| 成功输出 | 返回统一的成功结果及对应对象、属性值、密文、明文、签名或公钥数据 |
| 失败输出 | 返回统一的 HSED 失败结果；供应商 SDK 专用错误不得直接泄漏为不稳定的上层契约 |
| 外部对象 | 目标平台选用的供应商 SDK、硬件加密设备及其密钥槽位 |

### 业务规则

- BSC HSE 必须完整承载上述 11 项能力；SPC 上层服务不得绕过该组件直接调用供应商 SDK 完成同类操作。
- HSED 对外 SPC 接口名称、参数、返回结果及既有调用流程保持不变；组件化不得要求现有 SPC 客户端改造。
- `HsedAlgorithm`、`HsedPropertyId`、属性组合、数据格式和长度规则以 `doc/hsed.xlsx` 为权威来源；组件不得另行定义相互冲突的业务语义。
- `key_id` 始终表示硬件加密设备的密钥槽位，不得解释为用户、进程或会话标识。
- `session_id` 或对象归属仍受创建该会话的 SPC 客户端连接约束，不得因组件化而允许跨进程或跨连接共享。
- 对供应商 SDK 的调用结果必须转换为统一的 `HsedResult`。参数非法、能力不支持、权限不足、密钥不存在、槽位占用、忙、资源不足、超时、设备不可用、认证锁定和设备错误应保持可区分。
- 供应商 SDK 不支持某个已请求算法、模式或操作时，必须明确返回不支持；不得伪造成功结果或静默改用不同算法。
- 同一硬件加密设备的访问必须保持串行，不得因 SPC 并发请求导致 SDK 状态、硬件通信或分段操作交叉。
- 公钥导出必须使用固定公钥槽位；公钥导入当前统一返回 `PERMISSION_DENIED` 且不访问芯片；不得增加私钥导出能力。
- 组件化不得扩大当前产品范围。首期仍不提供私钥导出、验签、密钥生成、密钥删除、摘要、随机数和固件升级能力。
- 切换供应商 SDK 后，相同有效输入应维持相同的上层成功/失败语义；供应商固有限制导致的差异必须以明确结果暴露，不得形成未说明的隐式行为。

### 使用流程

1. HSED 启动并选择目标平台对应的硬件密码能力实现。
2. SPC 客户端按既有方式创建 HSED 对象，使用固定密钥槽位并配置所需可写属性。
3. SPC 上层服务将请求交给 BSC HSE 组件处理，不直接访问供应商 SDK。
4. BSC HSE 按统一语义校验请求，并使用目标平台供应商能力完成硬件操作。
5. BSC HSE 将执行结果转换为统一 HSED 结果和输出数据，SPC 上层服务按既有接口返回客户端。
6. 对象销毁或连接断开时，相关对象状态和资源按既有规则释放。

### 特殊情况

- 未配置或未提供目标平台供应商能力：组件初始化失败，HSED 明确报告设备不可用或不支持，不得启动为可正常处理密码请求的状态。
- 供应商 SDK 初始化失败、硬件未连接或通信异常：返回统一失败结果，并保留足够的服务端诊断信息。
- 输入在 HSED 规则内有效但超过供应商 SDK 实际限制：返回数据过大或不支持，不得截断输入后继续处理。
- 供应商 SDK 返回未知错误：转换为统一设备错误，并在服务日志中记录供应商诊断信息。
- 并发请求到达：请求按受控顺序访问硬件；不得出现响应数据串线或一个请求改变另一个请求的对象状态。
- 目标槽位不存在、角色不匹配、已占用或正在使用：返回对应统一结果，不得访问错误槽位或越权覆盖。

## Part 2：验收契约

### 验收标准

- [ ] [001] HSED SPC 的 11 项既有能力均通过独立 BSC HSE 组件完成，SPC 上层服务不存在直接调用供应商 SDK 完成这些能力的路径。
- [ ] [002] 组件化前后，`doc/hsed.xlsx` 中 11 项 SPC 接口的名称、参数方向、参数类型和统一返回语义保持一致，既有客户端无需修改即可调用。
- [ ] [003] 对象创建、对象销毁、四项属性读写、加密、解密、签名和公钥导出分别至少完成一次成功测试；公钥导入按当前策略返回 `PERMISSION_DENIED`。
- [ ] [004] 供应商 SDK 的成功、参数错误、不支持、超时、设备不可用及其他设备错误能够稳定转换为对应统一 HSED 结果，SPC 客户端不依赖供应商专用错误码。
- [ ] [005] 使用无效算法、无效属性组合、错误密钥槽位角色或供应商不支持的能力时，调用明确失败，且不得执行其他算法或报告成功。
- [ ] [006] 同一设备收到并发密码请求时，硬件访问保持串行；所有响应与原请求一一对应，输出数据和对象状态无交叉污染。
- [ ] [007] 更换为另一套测试适配或供应商适配后，SPC 上层服务和 `doc/hsed.xlsx` 无需修改即可完成构建，并可继续通过同一调用方式使用受支持能力。
- [ ] [008] SPC 上层服务的构建依赖中不直接引用供应商 SDK；未被选择的供应商 SDK 不成为当前目标的必需构建或运行依赖。
- [ ] [009] `key_id` 在全部能力中均作为硬件密钥槽位处理；对象或会话不得跨 SPC 客户端连接共享。
- [ ] [010] 公钥导出可用，公钥导入不能覆盖固定槽位，私钥无法通过组件或 SPC 接口导出。
- [ ] [011] 私钥导出、验签、密钥生成、密钥删除、摘要、随机数和固件升级未因本次组件化而新增为可用能力。
- [ ] [012] SDK 初始化失败、硬件不可用、通信超时及未知 SDK 错误均不会造成 HSED 崩溃或返回伪成功，并可通过统一结果和服务日志定位失败类别。

### 测试用例

#### MT001 全能力成功路径
- **测试步骤**：在目标设备和有效测试密钥条件下，依次执行对象创建、四项属性读写、加密、解密、签名、公钥导出、公钥导入和对象销毁。
- **预期结果**：全部调用均由 BSC HSE 处理；已交付操作返回预期结果，公钥导入返回 `PERMISSION_DENIED` 且固定公钥不变。
- **验收标准**：[001] [003]

#### MT002 SPC 契约兼容性
- **测试步骤**：使用组件化前可用的 SPC 客户端代码连接组件化后的 HSED，比较生成接口以及典型请求的输入输出。
- **预期结果**：客户端无需修改；接口名称、参数方向、参数类型和统一返回语义保持一致。
- **验收标准**：[002]

#### MT003 统一错误转换
- **测试步骤**：分别构造参数非法、供应商不支持、硬件超时、设备断开和供应商未知错误；通过 SPC 发起对应请求。
- **预期结果**：客户端分别获得稳定、可辨识的统一 HSED 结果；服务不崩溃，日志保留失败类别和供应商诊断信息。
- **验收标准**：[004] [012]

#### MT004 非法算法与槽位保护
- **测试步骤**：分别使用无效算法、算法与属性不匹配、使用公钥槽位签名、使用私钥槽位导入公钥以及不存在的槽位发起请求。
- **预期结果**：所有请求明确失败；未改用其他算法，未访问或覆盖错误槽位，未返回伪成功。
- **验收标准**：[005] [009] [010]

#### MT005 并发访问隔离
- **测试步骤**：由多个 SPC 客户端并发发起包含不同输入和不同对象属性的加密、解密及签名请求，并记录硬件执行顺序与响应归属。
- **预期结果**：硬件访问串行；每个响应与原请求匹配；不同客户端的对象、属性和数据互不污染，句柄不可跨连接使用。
- **验收标准**：[006] [009]

#### MT006 供应商适配切换
- **测试步骤**：在不修改 SPC 上层服务和 `doc/hsed.xlsx` 的条件下，分别选择两套可用适配（允许其中一套为测试适配）完成构建，并执行共同支持的典型能力测试。
- **预期结果**：两次构建均通过统一调用方式工作；当前目标只依赖所选适配所需的供应商能力，未选供应商 SDK 不是必需依赖。
- **验收标准**：[007] [008]

#### MT007 公私钥安全边界
- **测试步骤**：验证公钥正常导出；调用公钥导入并再次导出比较；随后尝试通过所有现有入口导出私钥。
- **预期结果**：公钥导出成功；导入返回 `PERMISSION_DENIED` 且原公钥不变；私钥无法导出。
- **验收标准**：[010]

#### MT008 范围回归
- **测试步骤**：检查 SPC 模型、BSC HSE 可用能力和运行入口，尝试调用私钥导出、验签、密钥生成、密钥删除、摘要、随机数和固件升级。
- **预期结果**：这些能力未新增为可用功能；11 项既有 SPC 能力不受影响。
- **验收标准**：[011]

## Part 3：非功能需求与实现影响提示

### 非功能需求

| 类型 | 用户可感知要求 | 验收方式 |
|---|---|---|
| 兼容性 | 现有 SPC 客户端无需因组件化或供应商切换而修改 | 执行 MT002、MT006 |
| 隔离性 | SPC 不直接依赖供应商 SDK，未选 SDK 不影响当前目标 | 执行 MT006并检查构建依赖 |
| 并发安全 | 同一硬件设备串行访问，请求、响应和对象状态不串线 | 执行 MT005 |
| 安全性 | 密钥槽位、连接归属、公钥覆盖和私钥禁止导出规则保持有效 | 执行 MT004、MT007 |
| 可诊断性 | SDK 和设备失败可通过统一结果及服务日志定位类别 | 执行 MT003 |
| 可替换性 | 新增或切换供应商适配不改变上层功能契约 | 执行 MT006 |

### 实现影响提示

| 类型 | 说明 |
|---|---|
| 组件边界 | 用户指定在 `framework/bsc_hse` 建立独立组件；具体目录、文件和组件接口由技术规范确定 |
| 依赖方向 | 目标关系为 SPC 上层服务依赖 BSC HSE，BSC HSE 再依赖所选供应商 SDK |
| SDK 隔离 | 供应商类型、头文件、数据结构、错误码和调用流程应限制在供应商适配范围内，不形成 SPC 上层契约 |
| 适配参考 | 可参考 `mcu_upgrade/mpu_upgrade` 使用统一能力声明并按目标平台选择具体实现的思路；是否完全沿用其文件组织由技术规范决定 |
| 迁移范围 | 现有 SPC 服务中与 11 项能力对应的具体硬件实现需要迁移到组件边界内 |
| 权威模型 | `doc/hsed.xlsx` 继续作为 HSED 对外 SPC 接口和业务语义的权威来源 |
| 技术设计 | 本需求涉及组件接口、供应商适配、构建选择、错误映射和串行化策略，需要独立技术规范 |
