## Part 1：功能契约

### 用户目标

系统集成和测试人员能够确认 HSED 在可控退出时完成 CIU98 通信资源清理，并将与 CIU98 相连的 SPI 引脚切换为 GPIO 低功耗状态，使 CIU98 在后续系统休眠期间保持规定的 Standby 引脚电平，避免因引脚状态不合理造成额外功耗。

### 使用场景

1. 系统准备休眠或停止业务时，通过 `SIGTERM` 正常停止 HSED。
2. 调试人员通过 `SIGINT` 中止 HSED。
3. HSED 正常服务流程、自检流程或初始化失败流程结束并退出。
4. 系统集成人员在目标板上测量 HSED 退出后的引脚状态和 CIU98 Standby 功耗。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 触发条件 | HSED 正常返回、收到可处理的 `SIGINT`/`SIGTERM`、自检完成，或初始化失败后进入退出清理 |
| 用户输入 | 无额外业务输入；沿用既有程序停止方式 |
| 引脚模式 | 退出清理完成后，CIU98 对应 `SPI_CS`、`SPI_SCK`、`SPI_MISO`、`SPI_MOSI` 均为 GPIO 模式 |
| 引脚电平 | `SPI_CS=高电平`、`SPI_SCK=低电平`、`SPI_MISO=高电平`、`SPI_MOSI=高电平` |
| 成功结果 | 退出日志可确认低功耗引脚状态设置成功，随后程序结束 |
| 失败结果 | 退出日志明确指出失败引脚或失败阶段；程序不得静默报告低功耗状态已设置成功 |

### 业务规则

- 所有 HSED 可控退出路径必须执行同一套 CIU98 SPI 低功耗清理，不得只覆盖正常服务退出而遗漏自检完成或初始化失败。
- 退出清理开始后不得再接受新的密码业务请求或发起新的 SPI 业务通信。
- 退出清理完成时，`SPI_CS`、`SPI_SCK`、`SPI_MISO`、`SPI_MOSI` 必须脱离 SPI 复用并切换为 GPIO 模式。
- GPIO 电平必须设置为：`SPI_CS=高`、`SPI_SCK=低`、`SPI_MISO=高`、`SPI_MOSI=高`。
- 四路引脚的模式和电平全部设置成功后，才可记录“SPI 低功耗状态设置成功”。
- 任一路引脚模式或电平设置失败时，必须记录具体失败对象和阶段；由普通返回路径触发退出时，最终进程结果必须反映清理失败。
- 已处于低功耗状态时重复执行退出清理，不得改变规定电平，也不得导致崩溃、死锁或重复释放错误。
- 本功能面向 CIU98 Standby 场景；在约定的目标板、供电和测量条件下，CIU98 Standby 功耗目标为小于 `200 µA`。
- `SIGKILL`、进程崩溃、操作系统失效和突然掉电等无法执行用户态退出清理的情况不属于本功能保证范围。
- RESET、VCC 的断电模式要求不在本规范中新增或变更；若系统进入断电模式，应遵循对应硬件规范另行处理。

### 使用流程

1. HSED 收到退出请求，或正常服务、自检、初始化流程决定结束。
2. HSED 停止接收新业务，并结束或停止当前可控的 CIU98 通信活动。
3. HSED 执行统一的 SPI 低功耗退出清理。
4. HSED 将四路 SPI 引脚切换为 GPIO，并设置规定电平。
5. HSED 记录清理结果，释放其余程序资源并退出。
6. 系统可继续进入休眠，测试人员可检查引脚模式、电平和 CIU98 Standby 功耗。

### 特殊情况

- HSED 尚未完成 CIU98 初始化即退出：只要相关引脚可能已被配置或占用，仍须尝试恢复规定的 GPIO 低功耗状态。
- SPI 从未成功打开：不得因设备句柄无效而跳过引脚低功耗设置。
- 某一路引脚设置失败：继续尝试设置其余引脚，并汇总记录所有失败项。
- 重复收到退出信号：退出清理只产生一致结果，不重复释放资源或改变目标电平。
- 自检成功或失败后退出：均执行相同的低功耗清理。
- 无法捕获或处理的强制终止：不承诺用户态清理已执行，系统级兜底方案需在技术规范中另行定义。

## Part 2：验收契约

### 验收标准

- [ ] [001] HSED 正常退出后，CIU98 对应 `SPI_CS`、`SPI_SCK`、`SPI_MISO`、`SPI_MOSI` 均处于 GPIO 模式。
- [ ] [002] 退出清理完成后，引脚电平为 `SPI_CS=高`、`SPI_SCK=低`、`SPI_MISO=高`、`SPI_MOSI=高`。
- [ ] [003] 通过 `SIGINT` 和 `SIGTERM` 停止 HSED 时，均执行低功耗清理并满足 [001]、[002]。
- [ ] [004] `--test-spi` 自检成功和自检失败退出时，均执行低功耗清理并满足 [001]、[002]。
- [ ] [005] CIU98 初始化中途失败，或 SPI 设备未成功打开时，只要程序进入可控退出流程，仍尝试设置四路引脚的 GPIO 模式和规定电平。
- [ ] [006] 任一路引脚模式或电平设置失败时，日志包含失败引脚和失败阶段，不得输出低功耗状态设置成功；普通返回路径的进程结果为失败。
- [ ] [007] 退出清理重复执行或重复收到退出信号时，程序无崩溃、死锁和重复释放错误，最终引脚状态仍满足 [001]、[002]。
- [ ] [008] 在约定的目标板、供电、温度和测量条件下，HSED 退出并完成低功耗清理后，测得 CIU98 Standby 功耗小于 `200 µA`。
- [ ] [009] 未触发退出时，HSED 既有 SPI 通信和正常密码业务行为不因本功能改变。

### 测试用例

#### MT001 正常服务退出

- **测试步骤**：启动 HSED 正常服务；确认 CIU98 通信可用；按正常停止流程结束 HSED；使用引脚复用状态查询手段和电平测量工具检查四路 SPI 引脚。
- **预期结果**：四路引脚均为 GPIO 模式；`SPI_CS=高`、`SPI_SCK=低`、`SPI_MISO=高`、`SPI_MOSI=高`；日志显示低功耗状态设置成功。
- **验收标准**：[001] [002]

#### MT002 信号退出

- **测试步骤**：分别启动 HSED 后发送 `SIGINT` 和 `SIGTERM`；每次等待进程退出，再检查四路引脚模式和电平。
- **预期结果**：两种信号退出均执行低功耗清理，最终引脚状态满足规定值，且无崩溃或死锁。
- **验收标准**：[001] [002] [003]

#### MT003 自检退出

- **测试步骤**：分别构造 `hsed --test-spi` 自检成功和自检失败场景；每次自检结束后检查四路引脚模式和电平。
- **预期结果**：无论自检结果成功或失败，进程退出前均完成低功耗清理，最终引脚状态满足规定值。
- **验收标准**：[001] [002] [004]

#### MT004 初始化失败退出

- **测试步骤**：分别构造 CIU98 初始化中途失败和 SPI 设备无法打开场景；等待 HSED 退出并检查日志、引脚模式和电平。
- **预期结果**：程序仍尝试设置全部四路引脚；能够设置的引脚达到规定状态；不得因无有效 SPI 设备句柄而崩溃。
- **验收标准**：[005]

#### MT005 单路设置失败

- **测试步骤**：通过可控故障注入使其中一路引脚的复用或电平设置失败，然后触发普通返回路径退出。
- **预期结果**：程序继续尝试其余引脚；日志明确记录失败引脚和阶段；不输出整体设置成功；进程结果为失败。
- **验收标准**：[006]

#### MT006 重复退出清理

- **测试步骤**：在退出阶段重复触发退出请求，或通过测试入口连续调用两次退出清理；检查程序行为和最终引脚状态。
- **预期结果**：无崩溃、死锁和重复释放错误；最终四路引脚模式及电平均符合规定。
- **验收标准**：[007]

#### MT007 Standby 功耗

- **测试步骤**：在约定的目标板、供电、温度和测量条件下启动 HSED；确认 CIU98 正常通信；可控退出 HSED；确认四路引脚达到规定状态后，测量 CIU98 所在供电支路的稳定 Standby 电流。
- **预期结果**：稳定 Standby 电流小于 `200 µA`，测量记录包含板卡版本、供电电压、温度、仪器和稳定等待时间。
- **验收标准**：[008]

#### MT008 运行态兼容性

- **测试步骤**：不触发退出，执行既有 SPI 通信、自检和代表性密码业务；观察通信结果和引脚复用状态。
- **预期结果**：运行期间按既有方式使用 SPI，业务结果与本功能加入前一致；不会提前切换为退出低功耗状态。
- **验收标准**：[009]

## Part 3：非功能需求与实现影响提示

### 非功能需求

| 类型 | 用户可感知要求 | 验收方式 |
|---|---|---|
| 低功耗 | 可控退出后保持规定引脚状态，CIU98 Standby 功耗小于 `200 µA` | 执行 MT001、MT007 |
| 可靠性 | 正常退出、信号退出、自检退出和初始化失败均执行一致清理 | 执行 MT001 至 MT004 |
| 可诊断性 | 失败日志可定位具体引脚和失败阶段 | 执行 MT005 |
| 幂等性 | 重复清理不崩溃、不死锁且最终状态一致 | 执行 MT006 |
| 兼容性 | 不改变 HSED 运行态 SPI 通信和既有业务行为 | 执行 MT008 |

### 实现影响提示

| 类型 | 说明 |
|---|---|
| 硬件依赖 | 依赖目标 MPU 的 SPI/GPIO 引脚复用与电平控制能力，以及 CIU98 Standby 电气要求 |
| 生命周期 | 所有可控退出路径需汇聚到统一的低功耗清理行为 |
| 异常处理 | 初始化未完成、设备未打开和部分引脚设置失败时仍需安全清理并报告结果 |
| 系统兜底 | `SIGKILL`、崩溃和掉电场景如需保证引脚状态，应由系统级方案补充 |
| 详细技术方案 | GPIO 编号、复用寄存器、访问方式、清理顺序和测试注入方式需由独立技术规范定义 |
