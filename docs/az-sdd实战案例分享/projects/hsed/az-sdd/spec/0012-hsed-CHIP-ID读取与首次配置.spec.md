## Part 1：功能契约

### 用户目标

授权的系统集成人员可以读取芯片标识，并只在芯片尚未配置时完成首次写入；普通业务不能覆盖已经存在的 CHIP_ID。

### 业务规则

- `CHIP_ID` 按 1～128 字节原始二进制处理。
- 未配置时允许具备权限的调用方首次写入；成功后再次写入返回 `KEY_OCCUPIED` 或 `PERMISSION_DENIED`，原值不变。
- 读取失败、通信异常或状态不明不得解释为“未配置”，也不得触发写入。
- 多对象读取同一芯片时应得到相同值；CHIP_ID 不属于对象私有数据。
- 当前代码对 CHIP_ID 读写统一返回 `UNSUPPORTED`。本规范批准并实现前，调用方不得依赖该能力。

## Part 2：验收契约

### 验收标准

- [ ] [001] 已配置芯片可完整读取 1～128 字节 CHIP_ID。
- [ ] [002] 未配置芯片只允许一次授权写入，后续写入不改变原值。
- [ ] [003] 通信失败或状态未知时不执行写入。
- [ ] [004] 多对象读取结果一致，且不能通过对象隔离绕过一次写入限制。

### 测试用例

#### MT001 读取与首次写入
- **测试步骤**：在未配置测试芯片上读取、授权写入合法 CHIP_ID，再通过多个对象读取并尝试第二次写入。
- **预期结果**：首次写入成功；各对象读取一致；第二次写入失败且原值不变。
- **验收标准**：[001] [002] [004]

#### MT002 异常状态保护
- **测试步骤**：分别构造通信失败、认证失败和未知状态后请求写入。
- **预期结果**：全部拒绝写入，芯片状态不变。
- **验收标准**：[003]
