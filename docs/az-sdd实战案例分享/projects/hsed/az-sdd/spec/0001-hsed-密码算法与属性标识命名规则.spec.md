## Part 1：功能契约

### 用户目标

HSED 调用方能够通过稳定、可读、可扩展的枚举名称和十六进制数值选择密码算法，并直接使用完整 `HsedPropertyId` 成员为同一个 HSE 对象保存多套算法属性，无需自行拼接属性 ID。

### 使用场景

1. 调用方为 AES、SM4、RSA、SM2 等算法设置各自的密钥槽位和运算属性。
2. 同一个 HSE 对象同时保存多种算法配置，执行操作时由显式算法参数选择对应属性组。
3. 后续新增同族算法时，在同一 `HsedPropertyId` 中增加相应的完整算法属性成员。
4. 评审人员仅查看算法标识即可判断算法类型、算法族、成员或代际以及规格序号。

### 输入与输出

| 项目 | 内容 |
|---|---|
| 输入 | `HsedAlgorithm`、完整 `HsedPropertyId` 以及属性值 |
| 输出 | 十六进制算法标识或可直接传给属性接口的完整属性枚举值 |
| 成功结果 | HSED 保存或读取指定算法属性组，业务操作使用完全匹配的属性组 |
| 失败结果 | 非法、未知、预留或不匹配的标识被拒绝，并返回明确错误码 |

### 类型和成员命名

- 算法枚举类型固定命名为 `HsedAlgorithm`。
- 完整属性枚举类型固定命名为 `HsedPropertyId`，公共属性和算法属性必须定义在同一个枚举中。
- 数据类型采用首字母大写驼峰形式，不带芯片型号或 SDK 前缀。
- 算法成员使用大写算法标准名称，密钥或摘要位数直接紧随名称，不使用下划线，例如 `AES128`、`RSA2048`、`SHA256`、`SM2`。
- 双长度 3DES 固定命名为 `TDES128`。
- 无算法固定命名为 `NONE`。
- 公共属性成员使用大写下划线形式，例如 `USER_ID`、`CHIP_ID`；算法属性成员使用 `<算法名>_<属性名>`，例如 `AES128_KEY_ID`、`RSA2048_HASH_ALGORITHM`。
- `HsedAlgorithm` 和 `HsedPropertyId` 的 Value 使用 `0x...` 十六进制写法，不使用十进制展示。
- 名称一经发布不得改名；弃用或预留的数值不得分配给其他名称。

### 16 位算法标识

算法标识格式为 `0xTFMS`：

| 位域 | 含义 | 规则 |
|---|---|---|
| `[15:12] T` | 算法类型 | `1` 对称、`2` 非对称、`3` 哈希 |
| `[11:8] F` | 算法族 | `1` AES、`2` DES、`3` SM、`4` RSA、`5` ECC、`6` SHA |
| `[7:4] M` | 成员或代际 | SM 保存 x；SHA 保存 SHA-1/SHA-2；3DES 保存 3 |
| `[3:0] S` | 规格序号 | 同族同成员下的密钥长度、摘要长度或曲线规格序号 |

首版算法标识：

| 名称 | 十六进制 | 十进制 | 分类 |
|---|---:|---:|---|
| `NONE` | `0x0000` | 0 | 无算法 |
| `AES128` | `0x1101` | 4353 | 对称/AES/规格1 |
| `TDES128` | `0x1231` | 4657 | 对称/DES/3DES/规格1 |
| `SM1` | `0x1310` | 4880 | 对称/SM/成员1 |
| `SM4` | `0x1340` | 4928 | 对称/SM/成员4 |
| `RSA1024` | `0x2401` | 9217 | 非对称/RSA/规格1 |
| `RSA2048` | `0x2402` | 9218 | 非对称/RSA/规格2 |
| `ECC256` | `0x2501` | 9473 | 非对称/ECC/规格1 |
| `SM2` | `0x2320` | 8992 | 非对称/SM/成员2 |
| `SM9` | `0x2390` | 9104 | 非对称/SM/成员9 |
| `SHA1` | `0x3610` | 13840 | 哈希/SHA/SHA-1 |
| `SHA256` | `0x3622` | 13858 | 哈希/SHA/SHA-2/规格2 |
| `SHA384` | `0x3623` | 13859 | 哈希/SHA/SHA-2/规格3 |
| `SHA512` | `0x3624` | 13860 | 哈希/SHA/SHA-2/规格4 |
| `SM3` | `0x3330` | 13104 | 哈希/SM/成员3 |

`SHA224=0x3621`、`AES192=0x1102`、`AES256=0x1103`、`RSA3072=0x2403`、`RSA4096=0x2404` 为预留标识，首版不得作为受支持算法使用。

### 完整属性枚举规则

`HsedPropertyId` 直接枚举所有可以传给属性接口的完整属性 ID。完整值为 32 位非负整数：`bits[31:24]` 固定为 0，`bits[23:8]` 为 `HsedAlgorithm`，`bits[7:0]` 为属性编号。

```text
property_id = (algorithm << 8) | property_code
```

| 编号 | 名称 | 作用域 |
|---:|---|---|
| `0x01` | `USER_ID` | 公共属性，算法段必须为 `NONE` |
| `0x02` | `CHIP_ID` | 公共属性，算法段必须为 `NONE` |
| `0x03` | `KEY_ID` | 算法属性 |
| `0x04` | `CIPHER_MODE` | 算法属性 |
| `0x05` | `PADDING` | 算法属性 |
| `0x06` | `HASH_ALGORITHM` | 算法属性，值为哈希类型 `HsedAlgorithm` 或 `NONE` |
| `0x07` | `SIGN_INPUT_MODE` | 算法属性 |
| `0x08` | `SM9_MODE` | 算法属性 |
| `0x09` | `IV` | 算法属性 |
| `0x0A` | `PUBLIC_KEY_FORMAT` | 算法属性 |
| `0x0B` | 保留 | 不定义独立属性；公钥覆盖控制由 `ImportPublicKey` 的 `replace_existing_key` 输入表达 |

上述公式用于定义和校验枚举值，不要求调用方运行时拼接。公共属性 `USER_ID` 固定为 `0x00000001`，`CHIP_ID` 固定为 `0x00000002`；算法属性按 `<算法名>_<属性名>` 直接生成，例如：

| 完整属性成员 | 十六进制值 |
|---|---:|
| `AES128_KEY_ID` | `0x00110103` |
| `CHIP_ID` | `0x00000002` |
| `SM4_IV` | `0x00134009` |
| `RSA2048_HASH_ALGORITHM` | `0x00240206` |
| `SM9_SM9_MODE` | `0x00239008` |

只生成算法实际支持的属性组合，不为无意义的算法/属性组合分配枚举成员。

### 使用流程

1. 调用方选择业务操作使用的 `HsedAlgorithm`。
2. 调用方直接选择同一算法对应的完整 `HsedPropertyId` 成员。
3. 调用方设置该枚举成员对应的属性值。
4. 调用方执行业务操作并再次显式传入同一个算法标识。
5. HSED 只使用与该算法完全匹配的属性组，不回退到其他算法属性。

### 特殊情况

- `bits[31:24]` 非 0、属性编号未知、公共属性携带算法或算法属性未携带算法时，返回 `INVALID_PARAM`。
- 未支持或预留算法返回 `UNSUPPORTED`。
- 属性类型错误、缺少必要属性或属性组与业务算法不匹配时，返回 `INVALID_PARAM`。
- 同一对象中不同算法的同名属性必须互不覆盖。

## Part 2：验收契约

### 验收标准

- [ ] [001] 对外模型只存在统一算法枚举 `HsedAlgorithm`，不再存在独立哈希算法枚举。
- [ ] [002] 所有首版算法名称、十六进制值和十进制值与本规范一致。
- [ ] [003] `SM1/SM2/SM3/SM4/SM9` 可通过相同 SM 算法族字段识别成员关系。
- [ ] [004] `SHA1/SHA256/SHA384/SHA512` 可通过相同 SHA 算法族字段识别代际和规格关系。
- [ ] [005] `USER_ID`、`CHIP_ID` 和算法属性均定义在 `HsedPropertyId` 中，算法属性成员采用 `<算法名>_<属性名>` 命名，且不存在独立的 `REPLACE_EXISTING_KEY` 属性。
- [ ] [006] 四个属性接口直接接受 `HsedPropertyId`，调用方无需运行时拼接属性 ID。
- [ ] [007] 同一 HSE 对象可保存至少两种算法的同名属性，读取时互不覆盖。
- [ ] [008] 业务操作只读取与显式算法参数完全匹配的属性组。
- [ ] [009] 保留高字节、未知编号、预留算法及错误属性组合在进入加密芯片前被拒绝。
- [ ] [010] SPC 接口模型能够成功生成，且生成结果保留全部业务接口的算法参数。

### 测试用例

#### MT001 算法名称和值核对
- **测试步骤**：检查权威接口模型和生成的数据类型文件中的全部 `HsedAlgorithm` 成员。
- **预期结果**：名称及数值与本规范表格完全一致，不存在独立哈希算法枚举。
- **验收标准**：[001] [002] [003] [004]

#### MT002 完整属性枚举验证
- **测试步骤**：检查 `USER_ID`、`CHIP_ID`、`AES128_KEY_ID`、`SM4_IV` 和 `RSA2048_HASH_ALGORITHM` 枚举成员及其 Value，并检查不存在独立 `REPLACE_EXISTING_KEY` 属性。
- **预期结果**：Value 分别以十六进制写为 `0x00000001`、`0x00000002`、`0x00110103`、`0x00134009` 和 `0x00240206`，无需调用方再次拼接；公钥覆盖由导入操作的独立输入控制。
- **验收标准**：[005] [006]

#### MT003 多算法属性隔离
- **测试步骤**：在同一对象中分别设置 AES128 与 SM4 的 `KEY_ID`，随后按完整属性 ID 读取。
- **预期结果**：两个值分别返回且互不覆盖。
- **验收标准**：[007]

#### MT004 业务算法精确匹配
- **测试步骤**：仅设置 AES128 属性组，然后以 SM4 执行加密。
- **预期结果**：HSED 不使用 AES128 属性作为回退，返回 `INVALID_PARAM`。
- **验收标准**：[008]

#### MT005 非法标识拒绝
- **测试步骤**：依次传入保留高字节非0、未知属性编号、预留算法和公共属性携带具体算法的属性 ID。
- **预期结果**：分别返回 `INVALID_PARAM` 或 `UNSUPPORTED`，且芯片未被调用。
- **验收标准**：[009]

#### MT006 SPC 模型生成
- **测试步骤**：使用项目提供的 SPC Builder 生成接口代码并检查属性与业务接口签名。
- **预期结果**：生成成功；四个属性接口参数类型为 `HsedPropertyId`；生成的 C 枚举保留 `0x...` 十六进制值；密码业务接口保留 `HsedAlgorithm` 参数。
- **验收标准**：[010]

## Part 3：非功能需求与实现影响提示

### 非功能需求

| 类型 | 用户可感知要求 | 验收方式 |
|---|---|---|
| 稳定性 | 已发布的算法名称、属性名称和数值不得重用或改变含义 | 对比版本间枚举清单 |
| 可读性 | 查看标识可识别算法类型、算法族、成员或代际和规格 | 按位域解析代表性标识 |
| 可扩展性 | 新算法在同一 `HsedPropertyId` 中增加有效属性成员，不改变属性接口 | 检查新增成员命名和值格式 |
| 隔离性 | 同一对象的不同算法属性互不影响 | 执行 MT003 |

### 实现影响提示

| 类型 | 说明 |
|---|---|
| 权威模型 | 对外名称和值以 `doc/hsed.xlsx` 为准 |
| 外部依赖 | CIU98 SDK 使用独立内部算法编号，HSED 需要保持稳定映射 |
| 生成工具 | 使用 `doc/spc-build.bat` 验证模型可生成 |
| 兼容性 | 本规范直接启用新算法值，不兼容旧的顺序编号 |
