# azKits 案例：AI Coding 使用 az-sdd 与不使用 az-sdd 的效果对比

## 一、实验设计

本案例以 azKits（Windows 离线终端脚本工具箱）为题目，在**两个独立文件夹**内分别实现**同一个功能（0014 脚本收藏与最近使用）**，对比 AI Coding 过程中使用 az-sdd 与不使用 az-sdd 的效果差异。

| 对比维度 | 对照组（不使用 az-sdd） | 实验组（使用 az-sdd） |
|----------|------------------------|----------------------|
| 功能主题 | 0014 脚本收藏与最近使用 | 0014 脚本收藏与最近使用 |
| 初始状态 | 空文件夹 | 空文件夹 + 预拷贝 `az-sdd/` 档案（无任何源码） |
| 源码 | 全部从 0 生成 | 全部从 0 生成 |
| 流程约束 | 显式禁止创建规范/档案/分阶段汇报 | 按 `/az-sdd-spec → arch → coder → tester` 推进 |
| 功能需求 | 同一份【共享需求描述】 | 同一份【共享需求描述】 |
| 验收标准 | 同一份【固定验收核对表】 | 同一份【固定验收核对表】 |

### 公平性保证

- 两组使用**同一模型**、粘贴**同一段需求描述**、从**空文件夹**开始。
- 两组共用相同的技术栈约束（Go 1.26.x + Bubble Tea v2 + Bubbles v2 + `go.yaml.in/yaml/v4`），避免技术选型差异干扰对比。
- 实验组 `az-sdd/` 档案来自当前 azKits 仓库（含 0010-0013 规范、0010 技术规范与状态档案），但源码文件一律不拷贝。
- 结果用同一份【固定验收核对表】评分，保证口径一致。

1. 创建两个空文件夹，例如：

   - `C:\JPZ_Workspace\AZ_TOOLS\azKits\_case\no-sdd\`（对照组）
   - `C:\JPZ_Workspace\AZ_TOOLS\azKits\_case\with-sdd\`（实验组）

2. 实验组额外操作：把当前仓库的 `az-sdd/` 目录完整拷贝到 `_case\with-sdd\az-sdd\`。

   ```powershell
   Copy-Item -Recurse -Path "C:\JPZ_Workspace\AZ_TOOLS\azKits\az-sdd" -Destination "C:\JPZ_Workspace\AZ_TOOLS\azKits\_case\with-sdd\az-sdd"
   ```

   > 注意：只拷贝 `az-sdd/` 档案，不要拷贝 `cmd/`、`internal/`、`examples/` 等源码。

3. 分别把提示词集 A / 提示词集 B 粘贴到对应文件夹的会话中开始实验。

## 三、共享需求描述（两组通用）

> azKits 是 Windows 离线终端脚本工具箱，目标平台 Windows 10/11 amd64。技术栈沿用项目既定约束：Go 1.26.x，TUI 用 Bubble Tea v2 + Bubbles v2，YAML 用 `go.yaml.in/yaml/v4` 严格解析；每个 YAML 入口对应一个独立进程和终端实例；真实脚本通过显式 argv 与独立子进程执行，禁止解释任意自由命令。
>
> 现有基础能力（本案例需一并从 0 实现）：
> - YAML 入口加载与严格校验：`version` 只接受 `1`，未知字段校验失败；启用脚本的 `id`、`alias`、`name`、`description`、`path` 必须非空，`id`/`alias` 在单个入口内唯一；`args` 只能是字符串数组且运行时不能追加自由参数；`type` 支持 `auto`、`bat`、`cmd`、`powershell`、`python`、`shell`、`exe`；`encoding` 支持 `utf-8`、`utf-8-sig`、`gbk`、`gb18030`；`interactive` 为可选布尔值。
> - 非交互命令：`list`（输出脚本及名称、简述、状态）、`run <alias>`（运行唯一匹配的有效脚本）、`check`（检查入口是否可加载并报告阻塞问题）。
> - TUI 斜杠命令交互：输入 `/` 显示候选，渐进过滤（完整别名优先、前缀次之、包含最后），`↑`/`↓` 移动选择，`Tab` 只补全不执行，`Enter` 执行明确选中项，`Esc` 关闭候选不执行；成功启动后输入行清空并可浏览当前实例命令历史；中文输入法组词、选字、上屏期间不得误执行。
>
> 本次新增功能 0014：
> 1. **收藏**：用户可将脚本标记/取消收藏，收藏脚本在斜杠候选列表置顶并带收藏标识。
> 2. **最近使用**：按最近成功启动时间展示最近使用脚本，同一脚本只保留最近一次，支持一键再次触发。
> 3. **展示规则**：输入 `/` 时候选顶部先显示收藏脚本，再按最近使用排序（收藏且最近使用的去重），其余按原匹配规则；候选同时显示收藏/最近使用标识、脚本名称、功能简述与状态。
> 4. **键盘行为**：复用既有规则（`↑`/`↓`/`Tab`/`Enter`/`Esc`），不新增鼠标操作。
> 5. **非交互联动**：`list` 输出标识收藏脚本；`run <alias>` 对收藏/最近使用脚本同样可用。
> 6. **持久化**：收藏属于用户偏好，需在不同终端实例间保持一致，因此需要落盘持久化；最近使用属于本次使用记录，不跨实例、不落盘，重启后为空。存储位置与格式由实现方案决定。
> 7. **健壮性**：脚本被删除或重命名后，收藏与最近使用记录不得导致启动失败，需降级处理。
> 8. **空态**：无收藏或无可执行脚本时显示友好提示。
> 9. **性能**：500 个启用脚本时，每次有效输入后候选更新不超过 50 毫秒。
> 10. **离线与中文**：断网下全部可用；中文名称、标识与提示无乱码。
>
> 验收目标：用户用最少按键即可触发收藏与最近使用的脚本；不同终端实例重启后收藏保持一致、最近使用清空。
