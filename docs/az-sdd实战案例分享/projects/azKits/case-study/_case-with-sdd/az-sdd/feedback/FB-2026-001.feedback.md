## 原始描述

> 命令执行完成后，输入框没有清空，如果想执行其他命令还需要先删除再输入很麻烦。这里希望优化成执行完成后输入框清空，如果想重复运行可以通过按上下键切换历史记录。

## 问题场景

用户在 TUI 输入斜杠命令并按 `Enter` 成功启动脚本后，输入行仍保留刚执行的命令。继续执行其他命令前需要手动删除旧内容，重复操作成本较高。

## 期望行为

1. 命令成功启动后立即清空输入行，并关闭当前候选。
2. 成功启动的命令写入当前终端实例的内存历史。
3. 输入行为空或正在浏览历史时，`↑` 显示较旧命令，`↓` 显示较新命令；越过最新记录后恢复空输入。
4. 从历史调出的命令仍可编辑，并可按 `Enter` 再次执行。
5. 命令校验或启动失败时保留输入，方便修正或重试，且失败命令不写入历史。
6. 历史仅存在于当前进程，不跨终端实例、不落盘。

## 经验沉淀

- 根因：TUI 的 `Enter` 成功路径只调用 `Core.Execute` 并更新提示，未同步清空 Bubbles `textinput` 与 Core 输入；Model 也没有实例内历史及历史游标状态。
- 解决方式：由 TUI Model 统一维护命令历史、游标与浏览状态；只有 `Start` 成功后才记录命令并同时清空 textinput/Core，失败路径保持输入；上下键按候选状态和历史状态分流。
- 验证证据：`go test ./...`、覆盖率、`go test -race ./...`、`go vet ./...`、构建与配置检查均通过；MT010、MT011 由用户确认通过。
- 预防建议：新增键盘状态时同时覆盖 UI 组件值与业务 Core 值的一致性；对 Enter 成功/失败、历史边界、实例隔离建立消息驱动回归测试。
