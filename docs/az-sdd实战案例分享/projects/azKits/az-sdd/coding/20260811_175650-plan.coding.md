## 一、任务目标

依据已批准的三份功能规范和统一技术规范，将现有 Python/Tkinter/JSON 原型迁移为 Windows 离线 Go TUI 工具箱：

1. 使用 UTF-8 YAML 作为唯一新产品入口，严格校验并以入口目录解析相对路径。
2. 提供共享同一配置、Catalog、任务状态和错误规则的 TUI 与 `list`、`run <alias>`、`check` 命令。
3. 支持 BAT、CMD、PowerShell、Python、Shell、EXE 子进程，保持 argv 边界、输出解码、重复运行控制和有界日志。
4. 以独立 OS 进程实现多入口终端实例，隔离配置、任务和日志。
5. 实现斜杠候选、中文过滤、稳定排序、方向键、`Tab` 补全、`Enter` 执行和 `Esc` 取消。
6. 交付单个 Windows 控制台 EXE、自动化测试、测试报告、人工验收手册和性能验证证据。

旧 `azKits.py`、`azKits.json` 与 `run_azKits.bat` 原计划保留至验收；2026-08-11 用户明确批准提前清理，Go/YAML 现为唯一产品入口。仍保留 `examples/demo.py` 用于验证 Python 类型脚本执行能力。

## 四、执行计划

### P0：状态切换与工程骨架

- 将 0010、0011、0012 按规则从“已批准”更新为“开发中”，同步 `SPEC.md`、`STATUS.md`、`TRACK.md`。
- 建立 Go module、`cmd/azkits`、`internal/*`、`testdata` 和示例 YAML。
- 固定 Bubble Tea v2、Bubbles v2、YAML v4、x/text 依赖版本与 `go.sum`。
- 验证目标：`go test ./...` 能运行空骨架。

### P1：配置、Catalog 与 CLI-First

- 先写失败测试，再实现 YAML 严格解码、版本/未知字段/必填项/重复 ID 与 alias/编码/路径校验。
- 实现只读 Catalog、启用过滤、别名查找和完整/前缀/包含稳定排序。
- 实现 `check`、`list` 的固定参数、stdout/stderr 和退出码。
- 增加 500 条候选 benchmark，目标单次更新小于 50 ms。

### P2：Runner、任务服务与日志

- 先测试各脚本类型 argv，再实现 BAT/CMD、PowerShell、Python、Shell、EXE 和 auto 分派。
- stdout/stderr 独立事件、UTF-8/GBK/GB18030 流式解码、有界 16 MiB 日志和截断提示。
- 实现 `TaskRegistry` 原子状态转换、重复启动拒绝、停止与退出码映射。
- 实现 `run <alias>` 集成测试，验证固定参数边界、非零退出、长行和中文输出。

### P3：最小 TUI 与中文 IME 原型门禁

- 基于 Bubble Tea/Bubbles 建立最小输入原型，只连接 Catalog，不先铺开完整页面。
- 自动化验证 `/`、Unicode 文本提交、方向键、`Tab`、独立 `Enter`、`Esc` 和无匹配状态。
- 构建 IME 原型，提交 Windows Terminal、Console Host、微软拼音的人工验证步骤。
- 门禁：确认中文组词/选字上屏不会同时执行脚本后，才进入 P4；若事件不可区分，实现 Windows 输入适配层。

### P4：完整 TUI、共享状态与多实例

- 实现集合页头、入口绝对路径、候选列表、状态、日志 viewport、重载和退出处理。
- TUI 与 CLI 共用 Config/Catalog/ScriptService，不复制过滤或执行规则。
- 每个进程只拥有一个入口、TaskRegistry 和日志缓冲；用双进程集成测试验证隔离。
- 未指定入口时只在终端读取 YAML 路径，空输入按用户取消退出，不扫描目录、不打开 GUI。

### P5：全量测试、构建与状态收口

- 依次更新状态“开发中 → 测试中 → 待验收”，每次同步 spec、索引、STATUS 与 TRACK。
- 执行 `go test ./...`、`go test -race ./...`、benchmark 和 Windows release 构建。
- 检查 EXE 不超过 10 MiB；记录空闲工作集、CPU 和离线人工验证步骤。
- 生成编码证据、自动测试报告和统一人工验收手册；保留所有 MT001... 用例及验收映射。
