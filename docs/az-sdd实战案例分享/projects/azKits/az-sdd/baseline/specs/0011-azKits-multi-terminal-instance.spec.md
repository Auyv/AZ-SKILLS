## 一、功能契约

### 1.1 功能目标

允许用户通过不同 YAML 入口启动不同用途的 azKits 终端实例，并同时运行多个相互独立的实例。每个入口定义工具集合名称、表述信息和可用脚本；每个实例只管理自身入口对应的配置、任务状态和日志。

### 1.2 目标用户

- 需要按项目、设备、测试阶段或业务场景拆分脚本集合的用户。
- 需要同时操作多个脚本集合且保持状态隔离的用户。
- 希望将一个 YAML 文件作为可复制工具集合入口的团队。

### 1.3 使用场景

#### 场景 A：指定入口启动

用户启动 azKits 时传入目标 YAML 路径，终端中显示该工具集合并进入其 TUI。

#### 场景 B：未指定入口启动

用户未提供 YAML 路径时，azKits 在终端中提示输入或选择可用入口；用户取消后正常退出，不启动空实例。

#### 场景 C：同时运行多个实例

用户在不同终端中分别加载不同 YAML，例如一个实例用于设备初始化，另一个实例用于回归测试。两个实例独立运行脚本并记录日志。

### 1.4 用户操作流程

1. 用户启动 azKits，并指定或在终端中选择一个 YAML 入口。
2. 工具校验入口，读取集合名称、表述信息和脚本清单。
3. 当前终端显示集合身份及已启用脚本。
4. 用户可另开终端，以另一入口启动第二个实例。
5. 各实例独立执行脚本、重新加载配置、显示状态和记录日志。
6. 任一实例退出时，不改变其他实例的运行状态。

### 1.5 输入项

#### 启动输入

| 输入 | 用途 | 必填 |
|------|------|------|
| YAML 入口文件路径 | 指定本次实例的工具集合 | 否；省略时在终端中选择 |

入口支持 `.yaml` 和 `.yml`。

#### YAML 工具集合信息

| 输入 | 用途 | 必填 |
|------|------|------|
| 工具集合名称 | 标识当前终端实例 | 是 |
| 工具集合表述信息 | 说明用途或适用场景，支持中文 | 是 |
| 脚本集合 | 定义当前实例允许展示和触发的脚本 | 是 |

脚本字段遵循 0010。

### 1.6 输出项

- 与入口 YAML 对应的独立终端实例。
- 终端中的工具集合名称、表述信息和入口位置。
- 当前入口内已启用脚本、运行状态和日志。
- 入口加载失败时可理解的中文错误提示。

### 1.7 功能范围

#### 本功能包含

- 通过启动参数指定 YAML 入口。
- 未指定入口时在终端内完成入口选择或取消。
- 同时运行多个由不同 YAML 驱动的终端实例。
- 配置、脚本状态、日志和重新加载的实例隔离。
- 相对脚本路径以入口 YAML 所在目录为参照。

#### 本功能不包含

- 图形文件选择器、图形窗口或桌面多窗口管理。
- 自动扫描并批量打开目录中的所有 YAML。
- 修改系统文件关联。
- 跨实例合并日志、共享状态或调用脚本。
- 在线获取入口文件或脚本。
- 在 TUI 中编辑 YAML 内容。

### 1.8 特殊情况与处理

| 情况 | 用户可见行为 |
|------|--------------|
| 未提供入口路径 | 在终端内提示选择或输入入口 |
| 用户取消入口选择 | 不创建空实例，本次启动正常结束 |
| 入口不存在、不可读或格式错误 | 显示包含入口位置的错误，不进入 TUI 主界面 |
| 缺少集合名称或表述信息 | 提示缺失字段，不进入可执行状态 |
| 脚本集合为空 | 显示集合信息及“当前没有可用脚本” |
| 两个入口集合名称相同 | 同时显示各自入口位置以便区分 |
| 一个实例重新加载或退出 | 不影响其他实例 |
| YAML 或路径包含中文 | 正确加载和显示，不出现乱码 |

## 二、验收契约

### 2.1 验收标准

- [ ] [001] 指定有效 YAML 启动后，当前终端直接进入对应工具集合的 TUI。
- [ ] [002] 未指定入口时，入口选择在终端内完成；取消后不创建空实例。
- [ ] [003] 集合名称、表述信息和入口位置在当前终端清晰可见，中文无乱码。
- [ ] [004] 当前实例仅加载自身入口中已声明且启用的脚本。
- [ ] [005] 两个不同入口可以在两个终端中同时运行并显示各自集合信息。
- [ ] [006] 任一实例中的脚本、状态、日志和配置重新加载不影响另一个实例。
- [ ] [007] 相对脚本路径以各自 YAML 所在目录为参照。
- [ ] [008] 入口无效或缺少必填集合信息时显示错误且不进入可执行状态。
- [ ] [009] 集合名称相同时，可通过入口位置区分实例。
- [ ] [010] 断网环境中可加载并同时运行多个本地入口实例。

### 2.2 人工测试用例

#### MT001 指定入口启动验证

- **前置条件**：准备含集合信息和有效脚本的 YAML。
- **测试步骤**：指定该 YAML 启动 azKits。
- **预期结果**：当前终端显示正确集合信息和脚本，仅使用 TUI。
- **验收标准**：[001] [003] [004]

#### MT002 终端入口选择验证

- **前置条件**：准备一个有效 YAML。
- **测试步骤**：不传入口启动并选择该 YAML；再次启动后取消。
- **预期结果**：选择后进入正确实例；取消后正常退出且无空实例。
- **验收标准**：[002]

#### MT003 多终端实例隔离验证

- **前置条件**：A、B 两个入口包含不同集合和脚本。
- **测试步骤**：在两个终端分别启动；运行脚本并重新加载其中一个入口。
- **预期结果**：两个实例同时存在，配置、状态和日志互不影响。
- **验收标准**：[005] [006]

#### MT004 相对路径验证

- **前置条件**：两个入口位于不同目录，均使用相对脚本路径。
- **测试步骤**：分别启动并运行各自脚本。
- **预期结果**：均以自身入口目录解析并运行正确脚本。
- **验收标准**：[007]

#### MT005 异常入口与同名集合验证

- **前置条件**：准备无效入口、缺字段入口及两个同名集合入口。
- **测试步骤**：分别启动这些入口。
- **预期结果**：无效入口不进入执行状态；同名集合通过入口位置可区分。
- **验收标准**：[008] [009]

#### MT006 离线多实例验证

- **前置条件**：断开网络，A、B 入口和脚本均在本机。
- **测试步骤**：同时启动两个实例并分别运行脚本。
- **预期结果**：两个实例均正常工作，不请求网络或 AI 服务。
- **验收标准**：[010]
