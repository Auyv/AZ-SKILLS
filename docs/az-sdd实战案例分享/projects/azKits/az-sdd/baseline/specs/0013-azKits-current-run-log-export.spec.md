## 一、功能契约

### 1.1 功能目标

脚本执行结束并返回 azKits TUI 主界面后，用户可按 `Ctrl+P` 将当前终端实例最近一次执行的完整过程导出为本地文本文档，并使用 Notepad++ 或 Notepad 打开查看、编辑和另存。

该功能用于快速保留和分享一次测试过程，不改变原脚本运行结果，也不混入其他脚本、其他入口实例或更早执行的日志。

### 1.2 目标用户

- 需要保存一次测试脚本执行过程用于分析或反馈的测试人员。
- 需要将日志整理、复制或另存为其他文档的开发人员。
- 同时运行多个 azKits 终端实例，需要准确区分日志来源的用户。

### 1.3 使用场景

#### 场景 A：导出最近一次成功执行

脚本执行成功并返回主界面后，用户按 `Ctrl+P`。azKits 生成文本文档，打开可用的文本编辑器，并在 TUI 中显示导出位置。

#### 场景 B：导出失败或异常退出过程

脚本返回失败状态或异常退出后，用户仍可导出本次已捕获的输出、错误信息和退出结果，用于排查问题。

#### 场景 C：多个实例分别导出

用户同时运行多个 YAML 入口实例。每个实例按 `Ctrl+P` 时，只导出自身最近一次已结束的执行过程。

### 1.4 名词定义

| 名词 | 定义 |
|------|------|
| 本次执行 | 当前终端实例中最近一次已经结束并返回主界面的脚本运行 |
| 执行日志 | 本次执行的基本信息、标准输出、错误输出和退出结果 |
| 导出文档 | 保存到本地、可由 Notepad++ 或 Notepad 打开的 UTF-8 文本文档 |

### 1.5 用户操作流程

1. 用户在 azKits 中运行一个脚本。
2. 脚本成功、失败或被终止后，azKits 返回 TUI 主界面。
3. 用户按 `Ctrl+P`。
4. azKits 确认当前实例存在可导出的最近一次执行日志。
5. azKits 生成本地 UTF-8 文本文档。
6. azKits 优先使用 Notepad++ 打开文档；Notepad++ 不可用时改用 Notepad。
7. TUI 显示导出成功、实际编辑器和文档位置。
8. 用户可在编辑器中查看、复制、编辑或另存文档。

### 1.6 导出内容

导出文档至少包含：

| 内容 | 要求 |
|------|------|
| 工具集合名称 | 标识日志来自哪个 YAML 工具集合 |
| 脚本名称与别名 | 标识本次运行目标 |
| 开始与结束时间 | 明确执行时间范围 |
| 执行结果 | 成功、失败、已终止等最终状态 |
| 退出码 | 存在退出码时完整记录 |
| 标准输出 | 保持本次执行的原始先后顺序 |
| 错误输出 | 保持本次执行的原始先后顺序 |

导出内容不得混入其他脚本或更早执行的日志。用于 TUI 显示的控制字符不得影响文档阅读。

### 1.7 编辑器选择规则

1. Notepad++ 可用时，优先使用 Notepad++ 打开导出文档。
2. Notepad++ 不可用或打开失败时，自动改用 Notepad。
3. Notepad 也无法打开时，导出文档仍应保留，并在 TUI 中显示文档位置和编辑器打开失败提示。
4. 编辑器打开失败不得被提示为日志导出失败；文件生成和编辑器打开结果应分别反馈。

### 1.8 输出项

- 一份保存到本地的 UTF-8 文本文档。
- TUI 中的导出成功或失败提示。
- 导出成功时显示完整文档位置。
- 编辑器成功打开时显示实际使用的编辑器。
- 编辑器打开失败时显示降级结果和人工打开方式。

### 1.9 功能范围

#### 本功能包含

- 在 TUI 主界面通过 `Ctrl+P` 触发导出。
- 导出当前实例最近一次已结束的完整执行日志。
- 成功、失败和已终止执行的日志导出。
- 生成可持续保留的 UTF-8 文本文档。
- Notepad++ 优先、Notepad 回退的打开行为。
- 多终端实例之间的日志导出隔离。

#### 本功能不包含

- 导出仍在运行中的未完成日志。
- 一次合并导出多次执行或多个脚本的日志。
- 导出其他终端实例的日志。
- 将日志上传到网络、云端或 AI 服务。
- 在 azKits TUI 内提供完整文本编辑能力。
- 使用图形按钮或鼠标触发导出。

### 1.10 特殊情况与处理

| 情况 | 用户可见行为 |
|------|--------------|
| 当前实例尚无已结束的脚本执行 | 提示“没有可导出的本次执行日志”，不创建空文档 |
| 脚本正在运行 | 不导出未完成日志，提示脚本结束并返回主界面后再操作 |
| 最近一次脚本没有产生输出 | 仍导出执行基本信息和退出结果，并标明没有输出 |
| 最近一次脚本执行失败或被终止 | 导出已捕获日志及最终状态，不因执行失败拒绝导出 |
| 文档写入失败 | 显示导出失败和原因，不启动编辑器，不覆盖已有文档 |
| Notepad++ 不可用 | 自动使用 Notepad，不要求用户重新操作 |
| 两种编辑器均无法打开 | 保留已导出的文档并显示位置和失败提示 |
| 连续执行多个脚本后按 `Ctrl+P` | 只导出最近一次已结束的执行日志 |
| 多实例同时运行 | 每个实例只导出自身日志 |
| 日志包含中文 | 导出文档正确显示中文，不出现乱码 |

## 二、验收契约

### 2.1 验收标准

- [ ] [001] 脚本执行结束并返回 TUI 主界面后，按 `Ctrl+P` 可触发本次执行日志导出。
- [ ] [002] 导出文档包含集合名称、脚本名称与别名、起止时间、执行结果、退出码以及本次标准输出和错误输出。
- [ ] [003] 导出文档只包含当前实例最近一次已结束的脚本执行，不混入其他执行日志。
- [ ] [004] 导出文档为本地 UTF-8 文本文档，中文名称和日志无乱码，TUI 显示完整保存位置。
- [ ] [005] Notepad++ 可用时，导出后使用 Notepad++ 打开文档。
- [ ] [006] Notepad++ 不可用或打开失败时，无需再次按键即可自动改用 Notepad 打开文档。
- [ ] [007] 两种编辑器均无法打开时，文档仍保留，TUI 分别提示导出成功和编辑器打开失败。
- [ ] [008] 当前实例没有已结束执行记录时，按 `Ctrl+P` 不创建空文档，并显示明确提示。
- [ ] [009] 脚本仍在运行时不导出未完成日志，并提示返回主界面后操作。
- [ ] [010] 成功、失败、异常退出或被终止的脚本均可在结束后导出已捕获过程和最终状态。
- [ ] [011] 文档写入失败时不启动编辑器、不覆盖已有文档，并显示失败原因。
- [ ] [012] 两个终端实例分别按 `Ctrl+P` 时，各自文档只包含自身最近一次执行日志。
- [ ] [013] 从按下 `Ctrl+P` 到 TUI 给出导出结果不超过 2 秒，不包含外部编辑器自身启动耗时。
- [ ] [014] 断网环境中可以完成日志导出和本地编辑器打开。

### 2.2 人工测试用例

#### MT001 成功执行日志导出验证

- **前置条件**：运行一个同时产生中文和英文输出并正常退出的脚本。
- **测试步骤**：脚本结束返回主界面后按 `Ctrl+P`，检查文档和 TUI 提示。
- **预期结果**：生成 UTF-8 文档；内容包含全部要求字段和正确日志；TUI 显示完整位置。
- **验收标准**：[001] [002] [004]

#### MT002 最近一次执行范围验证

- **前置条件**：依次运行输出内容不同的脚本 A、B。
- **测试步骤**：B 结束并返回主界面后按 `Ctrl+P`。
- **预期结果**：文档只包含 B 的执行信息和输出，不包含 A 的日志。
- **验收标准**：[003]

#### MT003 编辑器优先与回退验证

- **前置条件**：分别准备 Notepad++ 可用、不可用或打开失败的环境。
- **测试步骤**：在两种环境中分别导出日志。
- **预期结果**：Notepad++ 可用时由其打开；不可用时自动由 Notepad 打开，无需第二次操作。
- **验收标准**：[005] [006]

#### MT004 编辑器全部不可用验证

- **前置条件**：使 Notepad++ 和 Notepad 均无法打开文档。
- **测试步骤**：完成一次脚本执行后按 `Ctrl+P`。
- **预期结果**：文档已保存；TUI 显示保存位置，并单独提示编辑器打开失败。
- **验收标准**：[007]

#### MT005 无日志与运行中验证

- **前置条件**：准备一个尚未运行脚本的实例和一个脚本正在运行的实例。
- **测试步骤**：分别按 `Ctrl+P`。
- **预期结果**：均不创建空文档；分别提示无日志或等待脚本结束。
- **验收标准**：[008] [009]

#### MT006 失败及终止日志验证

- **前置条件**：准备异常退出脚本和可被用户终止的脚本。
- **测试步骤**：分别执行并在结束后导出。
- **预期结果**：两份文档均包含已捕获输出、对应最终状态和可用退出码。
- **验收标准**：[010]

#### MT007 写入失败验证

- **前置条件**：使导出位置不可写，并准备一个同名既有文档。
- **测试步骤**：按 `Ctrl+P` 导出。
- **预期结果**：TUI 显示写入失败原因；不启动编辑器；既有文档内容不变。
- **验收标准**：[011]

#### MT008 多终端实例隔离验证

- **前置条件**：A、B 两个终端实例分别运行输出不同内容的脚本。
- **测试步骤**：两个实例结束后分别按 `Ctrl+P`。
- **预期结果**：两份文档分别只包含对应实例的最近一次执行日志。
- **验收标准**：[012]

#### MT009 响应与离线验证

- **前置条件**：断开网络，准备一份包含大量输出的已完成执行日志。
- **测试步骤**：按 `Ctrl+P` 并记录 TUI 显示导出结果的时间。
- **预期结果**：2 秒内显示结果；日志导出和本地编辑器打开不依赖网络或 AI。
- **验收标准**：[013] [014]
