## 原始描述

> 执行过程过程中如果脚本中涉及了另外的交互逻辑会失效。比如 `C:\HQ_Workspace\hqt401_k00\doc\ecall过标相关\script\cfun.bat` 无法正常实现等待用户的按键按下。

## 问题场景

目标 BAT 在多条 `adb shell serial_atcmd` 命令之间使用三次 `pause` 等待用户按键。azKits 当前将脚本作为后台任务执行，只连接 stdout/stderr，不向子进程提供 stdin；同时 Bubble Tea TUI 持有终端输入，因此 `pause` 无法可靠接收用户按键。

## 根因证据

- `cfun.bat` 确认包含三次 `pause`。
- `internal/runner/runner.go` 使用 `StdoutPipe`、`StderrPipe`，但未设置 `cmd.Stdin`。
- Bubble Tea v2.0.8 提供 `tea.ExecProcess`，用于暂停 Program、释放终端给交互子进程、结束后恢复 TUI。
- 直接把 `os.Stdin` 交给现有后台 goroutine 会与 TUI 争抢同一终端输入，不能作为可靠修复。
- 经验库只命中无关的 WSL2 vsyscall 经验，语义判断为 `ERR_NO_MATCH`。

## 期望行为

1. YAML 脚本默认使用交互模式；无需读取键盘且需要并行操作 TUI 时，可显式配置为后台模式。
2. 在 TUI 运行交互脚本时，azKits 暂停 TUI 并把当前终端输入、输出和错误输出交给脚本。
3. `pause`、`set /p` 及其他从标准输入读取内容的脚本可正常等待和接收用户输入。
4. 脚本结束后恢复原 TUI，显示最终成功/失败状态和退出码，并保留可查看的输出记录。
5. 通过 `run <alias>` 启动交互脚本时，同样连接当前命令行的 stdin/stdout/stderr。
6. 普通脚本的后台执行、日志视口、重复运行控制和实例隔离行为保持不变。
