## 一、参考交互摘要

本功能参考 Codex CLI 的终端斜杠命令体验，只借鉴命令发现、渐进过滤和键盘确认方式，不复制其 AI、会话或云端能力。

用户在终端输入 `/` 后看到可用候选；继续输入使候选逐渐收敛；方向键移动选择；`Tab` 只补全；`Enter` 执行；`Esc` 取消候选。整个过程无需鼠标。

## 二、功能契约

### 2.1 功能目标

在 azKits TUI 中提供统一的斜杠命令交互，使用户在脚本较多时能快速发现、筛选并运行当前 YAML 中的脚本。交互必须支持中文、保持离线，并与非交互命令使用同一脚本清单和结果语义。

### 2.2 使用场景

#### 场景 A：发现可用脚本

用户输入 `/`，查看当前入口中全部已启用脚本及其功能简述。

#### 场景 B：快速定位并执行

用户输入中文名称或英文别名，使候选实时缩小；使用方向键选择，按 `Tab` 补全，再按 `Enter` 执行。

#### 场景 C：直接调用

用户不进入交互式 TUI，直接使用 `list`、`run <alias>` 或 `check` 完成对应操作。

### 2.3 TUI 组成

#### 输入行

- 默认可接收斜杠命令输入。
- 接受中文、英文、数字、连字符和下划线。
- 候选关闭后仍可继续进行终端操作。

#### 候选列表

每个候选至少显示：

| 内容 | 示例 | 用途 |
|------|------|------|
| 斜杠命令 | `/device-init` | 唯一命令别名 |
| 脚本名称 | 设备初始化 | 方便识别 |
| 功能简述 | 初始化设备并检查连接 | 执行前说明用途 |
| 当前状态 | 就绪 / 运行中 / 成功 / 失败 | 辅助判断是否执行 |

当前选中项必须明确可辨；候选超出可见范围时，选中项始终保持可见。

### 2.4 用户操作流程

1. 用户输入 `/`，TUI 显示当前入口全部已启用脚本。
2. 用户继续输入别名或名称，候选随输入收敛。
3. 第一条匹配项默认选中，用户用 `↑`、`↓` 移动选择。
4. 用户按 `Tab`，输入补全为当前候选的完整斜杠命令，但不运行脚本。
5. 用户按 `Enter`，工具校验命令和脚本状态。
6. 校验通过后运行对应真实脚本，并显示启动结果、日志和状态。
7. 用户按 `Esc` 时关闭候选且不执行脚本。
8. 脚本成功启动后，输入行立即清空，成功执行的命令加入当前实例历史。
9. 用户可用 `↑`、`↓` 浏览历史命令，调出后可编辑或再次执行；越过最新记录后恢复空输入。

### 2.5 匹配与排序行为

- 只匹配当前实例 YAML 中已启用脚本的命令别名、脚本名称和功能简述。
- 英文匹配不区分大小写；中文按已确认上屏内容匹配。
- 完整别名匹配优先，其次是前缀匹配，再其次是包含匹配。
- 同一匹配等级保持 YAML 配置顺序。
- 只有 `/` 时按 YAML 顺序显示全部候选。
- 禁用、未配置及其他实例的脚本不参与匹配。

### 2.6 键盘行为

| 操作 | 行为 |
|------|------|
| `/` | 显示脚本候选 |
| 继续输入 | 实时过滤候选 |
| `↑` / `↓` | 候选可见时移动当前选择；输入为空或正在浏览历史时切换命令历史 |
| `Tab` | 补全当前候选，不执行 |
| `Enter` | 执行完整匹配或明确选中的候选 |
| `Esc` | 关闭候选，不执行 |
| `Backspace` | 更新过滤；退回 `/` 时恢复全部候选 |

本功能不定义任何鼠标操作。

### 2.7 命令完成与历史记录

- `Enter` 成功启动脚本后立即清空输入行并关闭候选，无需等待脚本进程退出。
- 只有成功启动的完整命令写入历史；无匹配、校验失败或启动失败时保留原输入，且不写入历史。
- 历史按本终端实例中的执行顺序保存在内存中，不跨实例、不持久化。
- 输入为空时按 `↑` 从最新命令开始向较旧命令浏览；按 `↓` 向较新命令浏览，越过最新记录后恢复空输入。
- 从历史调出的命令可继续编辑；编辑后退出历史浏览状态，后续 `↑` 从最新历史重新开始。
- 从历史调出的命令按 `Enter` 可再次执行，并按一次新的成功执行写入历史。

### 2.8 中文输入法行为

- 中文输入法组词、翻页和选字期间不得误执行脚本。
- 中文确认上屏后，候选按最终文本更新。
- 输入法确认与脚本执行确认必须区分，一次上屏操作不得同时运行脚本。
- 中文名称、简述、错误和运行反馈不得乱码。

### 2.9 非交互命令行为

- `list`：输出当前入口的有效脚本及名称、简述和状态。
- `run <alias>`：运行唯一匹配的有效脚本；无匹配或冲突时失败。
- `check`：检查入口是否可加载，并报告所有阻止运行的问题。
- 非交互命令不得进入候选选择，也不得运行 YAML 外的任意命令。

### 2.10 功能范围

#### 本功能包含

- TUI 中的斜杠候选、渐进过滤和稳定排序。
- 全键盘导航、补全、执行和取消。
- 成功执行后清空输入及当前实例内的命令历史浏览。
- 中文名称检索与输入法防误触。
- 当前入口、当前实例范围内的脚本调用。
- 与非交互命令一致的配置和执行边界。

#### 本功能不包含

- 图形命令面板、鼠标选择、卡片或桌面界面。
- Codex 的 AI、权限、会话或云端能力。
- 执行 YAML 之外的任意系统命令。
- 在命令后追加未在 YAML 中定义的自由参数。
- 跨终端实例搜索或调用脚本。

### 2.11 特殊情况与处理

| 情况 | 用户可见行为 |
|------|--------------|
| 当前入口没有启用脚本 | 输入 `/` 后显示“当前没有可用脚本” |
| 没有匹配候选 | 显示“未找到匹配脚本”，`Tab` 和 `Enter` 不执行 |
| 别名重复 | 配置检查报告冲突，冲突脚本不可运行 |
| 脚本路径失效 | 显示错误，不创建运行任务 |
| 脚本正在运行 | 显示“运行中”，再次确认不重复启动 |
| 用户按 `Esc` | 关闭候选，不执行脚本 |
| 当前实例重新加载 YAML | 候选切换到新的有效清单，不保留失效条目 |
| 命令成功启动 | 输入行清空，命令加入当前实例历史 |
| 命令启动失败 | 保留输入供修正或重试，不写入历史 |
| 历史浏览到最新记录之后 | 输入行恢复为空 |

## 三、验收契约

### 3.1 验收标准

- [ ] [001] 用户无需鼠标即可完成脚本发现、筛选、补全和触发。
- [ ] [002] 输入 `/` 后只显示当前入口中已启用的脚本。
- [ ] [003] 候选显示命令、名称、简述和状态，中文无乱码。
- [ ] [004] 输入名称、别名或简述时，候选按完整、前缀、包含顺序实时收敛。
- [ ] [005] `↑`、`↓` 可移动选择且不越界，选中项始终可见。
- [ ] [006] `Tab` 只补全当前候选，不运行脚本。
- [ ] [007] `Enter` 只运行完整匹配或明确选中的当前入口脚本。
- [ ] [008] `Esc`、无匹配、别名冲突或路径失效时不运行脚本并给出提示。
- [ ] [009] 中文输入法组词、选字和上屏期间不会误执行脚本。
- [ ] [010] 同一脚本运行期间再次触发不会产生第二个实例。
- [ ] [011] 不同终端实例只检索和执行自身入口中的脚本。
- [ ] [012] `list`、`run <alias>`、`check` 与交互式 TUI 使用同一有效清单和错误规则。
- [ ] [013] 包含 500 个启用脚本时，每次有效输入后的候选更新不超过 50 毫秒。
- [ ] [014] 断网环境下候选、过滤、补全、校验和执行均正常。
- [ ] [015] 命令成功启动后输入行立即清空，失败时保留输入且失败命令不进入历史。
- [ ] [016] `↑`、`↓` 可按执行顺序浏览当前实例历史，越过最新记录恢复空输入，历史命令可编辑和重复执行。
- [ ] [017] 命令历史不跨终端实例、不落盘，重启后为空。

### 3.2 人工测试用例

#### MT001 斜杠唤起与候选内容验证

- **前置条件**：入口包含启用与禁用脚本，含中文名称和英文别名。
- **测试步骤**：输入 `/` 并检查候选。
- **预期结果**：只显示启用脚本，每项内容完整且中文无乱码。
- **验收标准**：[001] [002] [003]

#### MT002 渐进过滤与排序验证

- **前置条件**：配置完整、前缀和包含匹配的多个脚本。
- **测试步骤**：逐字输入中文名称、简述及不同大小写英文别名。
- **预期结果**：候选实时收敛并按规定排序。
- **验收标准**：[004]

#### MT003 键盘补全与执行验证

- **前置条件**：存在多个匹配候选。
- **测试步骤**：使用方向键选择，按 `Tab`，再按 `Enter`。
- **预期结果**：选择不越界；`Tab` 不执行；`Enter` 仅运行目标脚本。
- **验收标准**：[005] [006] [007]

#### MT004 取消与异常输入验证

- **前置条件**：准备无匹配输入、重复别名和失效路径。
- **测试步骤**：分别操作并在候选打开时按 `Esc`。
- **预期结果**：均不误运行脚本，并显示明确提示。
- **验收标准**：[008]

#### MT005 中文输入法验证

- **前置条件**：使用中文输入法并配置中文脚本名称。
- **测试步骤**：组词、翻页、选字、上屏后再明确按 `Enter`。
- **预期结果**：输入过程不运行脚本，上屏后候选正确更新，最终确认才执行。
- **验收标准**：[009]

#### MT006 重复触发与实例隔离验证

- **前置条件**：两个终端实例加载不同入口，其中一个脚本正在运行。
- **测试步骤**：重复触发该脚本，并在另一实例搜索它。
- **预期结果**：不重复启动；另一实例无法搜索或运行它。
- **验收标准**：[010] [011]

#### MT007 非交互一致性验证

- **前置条件**：准备有效和无效入口。
- **测试步骤**：对照 TUI 分别执行 `list`、`run <alias>`、`check`。
- **预期结果**：有效清单、运行目标和错误规则一致。
- **验收标准**：[012]

#### MT008 大量脚本响应验证

- **前置条件**：入口包含 500 个启用脚本。
- **测试步骤**：连续输入和删除检索字符，记录候选更新时间。
- **预期结果**：每次更新不超过 50 毫秒，输入连续。
- **验收标准**：[013]

#### MT009 离线调用验证

- **前置条件**：断开网络，入口和脚本均在本机。
- **测试步骤**：执行候选过滤、补全、检查和脚本运行。
- **预期结果**：全过程正常，不请求网络或 AI 服务。
- **验收标准**：[014]

#### MT010 输入清空与历史重复执行验证

- **前置条件**：当前实例至少配置两个可成功启动的脚本，并准备一个启动失败的脚本。
- **测试步骤**：依次成功执行两个不同命令；检查输入；按多次 `↑`、`↓`；从历史调出命令后编辑并再次执行；最后执行失败命令。
- **预期结果**：每次成功启动后输入为空；上下键按顺序切换历史并能回到空输入；历史命令可编辑和重复执行；失败后输入保留且失败命令不进入历史。
- **验收标准**：[015] [016]

#### MT011 命令历史实例隔离验证

- **前置条件**：启动两个终端实例，并在其中一个实例执行命令。
- **测试步骤**：分别在两个实例按 `↑`，再重启执行过命令的实例并按 `↑`。
- **预期结果**：历史只在执行命令的当前进程可见；另一实例和重启后的实例均无该历史。
- **验收标准**：[017]
