## 一、功能契约

### 1.1 功能目标

azKits 仅通过终端用户界面（TUI）提供脚本发现、触发、状态查看和日志查看能力。工具只加载当前 YAML 入口中已声明且启用的脚本，支持中文名称和功能简述，并在用户确认后运行对应的真实脚本。

除交互式 TUI 外，还应提供 `list`、`run <alias>`、`check` 等非交互命令，便于用户直接调用或集成到本地流程中。两种调用方式遵循同一份配置、校验规则和执行边界。

### 1.2 目标用户

- 需要集中管理和运行多组本地测试脚本的开发、测试人员。
- 希望用中文名称与功能简述识别脚本用途的用户。
- 需要键盘操作或非交互命令调用的用户。

### 1.3 使用场景

#### 场景 A：在 TUI 中浏览并运行

用户启动 azKits 后查看当前入口的工具集合信息和脚本列表，选择目标脚本并确认运行。

#### 场景 B：通过斜杠命令运行

用户在 TUI 中输入 `/` 唤起候选列表，逐步过滤并选择脚本。详细交互遵循 0012。

#### 场景 C：非交互调用

用户通过 `list` 查看脚本，通过 `run <alias>` 运行指定脚本，或通过 `check` 检查入口配置。

#### 场景 D：运行需要用户输入的脚本

用户运行在 YAML 中标记为交互模式的脚本。azKits 暂停自身 TUI，把当前终端交给脚本；脚本可通过 `pause`、`set /p` 或标准输入等待用户操作，结束后用户返回原 TUI。

### 1.4 用户操作流程

1. 用户使用指定 YAML 入口启动 azKits。
2. 工具校验入口并显示工具集合名称、表述信息和已启用脚本。
3. 用户通过列表选择或斜杠命令定位目标脚本。
4. 工具在执行前确认目标来自当前有效脚本清单且可运行。
5. 普通脚本作为后台任务运行，并持续显示运行状态、输出和退出结果。
6. 交互脚本在当前终端前台运行；TUI 暂停，脚本结束后恢复并显示最终状态和退出结果。
7. 用户可继续浏览其他脚本、停止允许停止的后台任务或退出当前实例。

### 1.5 输入项

每个脚本配置至少包括：

| 输入 | 用途 | 必填 |
|------|------|------|
| 命令别名 | 唯一定位脚本 | 是 |
| 脚本名称 | TUI 中的可读名称，支持中文 | 是 |
| 功能简述 | 说明脚本用途，支持中文 | 是 |
| 真实脚本路径 | 指向实际运行目标 | 是 |
| 是否启用 | 决定是否加载，默认启用 | 否 |
| 固定参数、工作目录、环境信息 | 固化运行上下文 | 否 |
| 是否为交互脚本 | 决定脚本是否需要接管当前终端输入，默认是 | 否 |

### 1.6 输出项

- 当前工具集合名称、表述信息和有效脚本列表。
- 脚本名称、功能简述和当前状态。
- 脚本运行输出、错误输出、退出状态和退出码。
- 交互脚本运行期间可直接看到提示并输入按键或文本；结束后返回 TUI。
- 配置或触发失败时可理解的中文提示。
- 非交互命令可判断成功或失败的结果。

### 1.7 功能范围

#### 本功能包含

- 仅使用 TUI 的交互式脚本管理。
- `list`、`run <alias>`、`check` 非交互命令。
- 从 YAML 加载脚本及其启用状态。
- 运行真实脚本并展示状态和日志。
- 显式配置的交互脚本可读取当前终端输入。
- 中文内容显示和离线运行。

#### 本功能不包含

- 图形界面、卡片、鼠标点击或桌面窗口交互。
- 扫描目录并自动发现未配置脚本。
- 执行 YAML 清单之外的任意系统命令。
- 在线下载脚本、连接 AI 服务或依赖网络。
- 在 azKits 中编辑真实脚本内容。

### 1.8 特殊情况与处理

| 情况 | 用户可见行为 |
|------|--------------|
| YAML 不存在、不可读或格式错误 | 显示明确错误，不进入可执行状态 |
| 脚本条目缺少必填项或别名重复 | 指出问题条目，不允许冲突脚本运行 |
| 真实脚本路径不存在 | 显示错误，不创建运行任务 |
| 当前入口没有启用脚本 | 显示“当前没有可用脚本” |
| 同一脚本正在运行时再次触发 | 不重复启动，并提示正在运行 |
| 脚本名称、路径或输出包含中文 | 正确显示，不出现乱码 |
| 脚本异常退出 | 保留输出并显示失败状态和退出码 |
| 显式后台脚本尝试读取输入 | 不自动猜测或抢占终端；应移除 `interactive: false` 或改为 `true` |
| 交互脚本等待输入 | TUI 暂停，按键或文本只交给当前交互脚本 |
| 交互脚本结束 | 恢复 TUI，显示最终状态和退出码，可继续执行其他脚本 |

## 二、验收契约

### 2.1 验收标准

- [ ] [001] azKits 只提供 TUI，不出现图形窗口、卡片或鼠标触发入口。
- [ ] [002] 启动后只显示当前 YAML 中已声明且启用的脚本。
- [ ] [003] 每个脚本显示名称、功能简述和状态，中文无乱码。
- [ ] [004] 用户从 TUI 选择并确认脚本后，运行对应真实脚本。
- [ ] [005] 脚本输出、错误输出、运行状态和退出码在当前实例中可见。
- [ ] [006] `list` 仅列出当前入口的有效脚本。
- [ ] [007] `run <alias>` 只运行当前入口中唯一匹配且已启用的脚本。
- [ ] [008] `check` 能区分有效配置与配置错误，并给出可理解提示。
- [ ] [009] 配置错误、路径失效或目标不匹配时不启动其他脚本。
- [ ] [010] 同一脚本运行期间再次触发不会产生第二个实例。
- [ ] [011] 修改并重新加载 YAML 后，有效脚本清单同步更新。
- [ ] [012] 断网环境中可完成加载、浏览、校验和脚本运行。
- [x] [013] 配置为交互模式的脚本可在 TUI 中通过标准输入等待并接收用户按键或文本。
- [x] [014] 交互脚本运行期间 TUI 不抢占按键，脚本结束后 TUI 正常恢复并显示最终状态和退出码。
- [x] [015] `run <alias>` 执行交互脚本时连接当前命令行 stdin/stdout/stderr。
- [x] [016] 显式配置 `interactive: false` 的普通脚本继续使用后台执行和日志视口，不受该能力影响。
- [x] [017] 交互模式不改变 YAML 清单、固定参数、重复运行和实例隔离边界。

### 2.2 人工测试用例

#### MT001 TUI 与加载范围验证

- **前置条件**：YAML 中有两个启用脚本、一个禁用脚本，目录中另有未配置脚本。
- **测试步骤**：启动 azKits 并查看脚本列表。
- **预期结果**：仅显示两个启用脚本，全程无图形界面或鼠标入口。
- **验收标准**：[001] [002]

#### MT002 中文显示与交互运行验证

- **前置条件**：配置中文名称、中文简述且可运行的脚本。
- **测试步骤**：在 TUI 中选择并确认该脚本。
- **预期结果**：中文无乱码；运行正确脚本并显示状态、输出和退出码。
- **验收标准**：[003] [004] [005]

#### MT003 非交互命令验证

- **前置条件**：准备一个有效入口和一个无效入口。
- **测试步骤**：分别执行 `list`、`run <alias>`、`check`。
- **预期结果**：列举、运行和校验结果符合当前入口，失败时不误运行脚本。
- **验收标准**：[006] [007] [008] [009]

#### MT004 重复触发验证

- **前置条件**：目标脚本正在运行。
- **测试步骤**：再次触发同一脚本。
- **预期结果**：不产生第二个实例，并显示正在运行提示。
- **验收标准**：[010]

#### MT005 配置重新加载验证

- **前置条件**：当前入口已成功加载。
- **测试步骤**：新增一个脚本、禁用一个脚本并重新加载。
- **预期结果**：列表按新配置更新，被禁用脚本不再可运行。
- **验收标准**：[011]

#### MT006 离线运行验证

- **前置条件**：断开网络，本地入口和脚本可用。
- **测试步骤**：加载、浏览、校验并运行脚本。
- **预期结果**：全过程正常，不请求网络或 AI 服务。
- **验收标准**：[012]

#### MT007 TUI 交互脚本按键等待验证

- **前置条件**：准备包含多次 `pause` 或标准输入读取的无副作用脚本，并在 YAML 中标记为交互模式。
- **测试步骤**：从 TUI 启动脚本，分别在每个等待点按键或输入文本，直至脚本退出。
- **预期结果**：每个等待点都会真实阻塞；按键只交给脚本；结束后恢复 TUI 并显示正确状态和退出码。
- **验收标准**：[013] [014]

#### MT008 非交互命令与后台模式回归验证

- **前置条件**：同时配置一个交互脚本和一个普通后台脚本。
- **测试步骤**：用 `run <alias>` 执行交互脚本并提供输入；再从 TUI 执行普通脚本。
- **预期结果**：交互脚本读取当前命令行输入；普通脚本仍在日志视口输出；两者均遵守清单、参数和实例边界。
- **验收标准**：[015] [016] [017]

#### MT009 cfun.bat 实机验证

- **前置条件**：ADB 设备已连接，将 `C:\HQ_Workspace\hqt401_k00\doc\ecall过标相关\script\cfun.bat` 配置为交互模式。
- **测试步骤**：从 TUI 启动该脚本，依次完成三次 `pause` 按键等待。
- **预期结果**：三次等待均不会被跳过；ADB 命令按原顺序执行；脚本结束后返回 TUI。
- **验收标准**：[013] [014] [017]
