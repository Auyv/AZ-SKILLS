# AZ-SDD-TESTER

人工测试验收 - 通过工单目录管理测试过程，为每个测试项单独生成测试单，支持异常记录与处理。

## 日常使用边界

- 仅在用户显式调用 `/az-sdd-tester`、`az-sdd tester`、`sdd tester`，或明确要求 AZ-SDD/SDD 验收时使用。
- 普通“跑测试”应优先使用项目已有测试命令，不生成验收工单。
- `lite` 模式只记录关键验收项；`standard` 生成测试单和汇总；`strict` 需要签名、异常处理和状态同步。
- Step 0 只确认应用可启动、可关闭和可进入人工验收，不重复执行 `az-sdd-coder` 已完成的完整自动化测试；若已有近期自测证据且代码未变，只引用该结果并执行最小前置检查。

## 目录结构

```
{项目目录}/
└── az-sdd/
    └── test/
        └── {工单目录}/              # 例如：20260514_203126/
            ├── test-summary.md       # 测试汇总报告
            └── cases/                # 测试单目录
                ├── MT001.md          # 测试项测试单
                ├── MT002.md
                └── ...
```

## 核心理念

```
┌─────────────────────────────────────────────────────────────┐
│  测试工单制 = 工单目录 + 单项测试单 + 异常处理流程             │
├─────────────────────────────────────────────────────────────┤
│  1. 创建工单目录（时间戳命名）                                 │
│  2. 检索待测试功能，生成测试单（每个测试项单独一份）            │
│  3. 用户按测试单执行测试，记录结果                            │
│  4. 如有异常，用户在测试单中描述具体情况                      │
│  5. AI 判断异常结论，处理修复或记录                          │
│  6. 测试完成后汇总，更新规范状态                              │
└─────────────────────────────────────────────────────────────┘
```

## 异常处理流程

当用户报告测试异常时：

```
═══════════════════════════════════════════════════════════════
🔍 异常分析

正在分析测试项 MTxxx 的异常描述...
```

### Step A1: 读取相关文件

1. 读取测试单 `az-sdd/test/{工单目录}/cases/MTxxx.md` 获取用户描述的异常
2. 读取功能规范文件获取规范要求

### Step A2: 判断结论是否正确

**根据功能规范分析用户的结论**：

```
═══════════════════════════════════════════════════════════════
📋 异常分析结果

测试项：MTxxx - {测试项标题}
用户结论：{用户的结论描述}
规范要求：{引用规范原文}

─────────────────────────────────────────────────────────────

AI 判断：{正确 / 不正确}

{分析说明}
```

### Step A3: 检查是否反复异常

如果同一测试项、同一界面/交互或同一用户期望连续 3 次修复后仍未通过，第 4 次处理前必须先降噪并升级判断：

1. 不继续把长篇异常原文追加到测试单；先在当前测试单中整理“已尝试方案 / 仍不满足点 / 当前阻塞判断”。
2. 用 2-3 个具体问题引导用户确认真实期望，例如目标行为、可接受替代方案、是否允许调整规范。
3. 判断问题属于实现缺陷、规范表达不清、技术方案不适配，还是需要重构；若需要重构或改规范，先明确告知用户再继续。

## 错误处理

| 情况 | 处理方式 |
|------|---------|
| 没有待测试功能 | 提示没有需要测试的功能 |
| 工单目录已存在 | 使用新的时间戳创建新工单 |
| 用户报告异常 | 按异常处理流程处理 |
| 有测试项未完成 | 询问是确认完成还是返回继续测试 |
