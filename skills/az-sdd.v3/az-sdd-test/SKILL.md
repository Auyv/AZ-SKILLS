# AZ-SDD-TEST

人工测试验收 - 通过 HTML 页面引导用户完成测试，测试完成后更新状态。

## 核心理念

```
┌─────────────────────────────────────────────────────────────┐
│  HTML 交互测试 = 自动检索 + 页面勾选 + 完成通知               │
├─────────────────────────────────────────────────────────────┤
│  1. AI 自动检索待测试功能和测试用例                           │
│  2. 生成测试总览 HTML 页面                                  │
│  3. 用户在页面查看测试项、打开规范文件、勾选完成               │
│  4. 用户关闭浏览器，回复"测试已完成"                          │
│  5. AI 检查结果，更新状态，生成报告                          │
└─────────────────────────────────────────────────────────────┘
```

## 执行步骤

### Step 0: 前置检查（应用启动/关闭）

```
┌─────────────────────────────────────────────────────────────┐
│  ⚠️  人工测试前置检查                                        │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  在进行人工测试前，必须确保应用可以正常启动和关闭。             │
│                                                              │
│  检查项目：                                                   │
│  1. 启动脚本是否存在？                                        │
│  2. 关闭脚本是否存在？                                        │
│  3. 应用能否正常启动？                                        │
│  4. 应用能否正常关闭？                                        │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**读取项目配置**：

1. 读取 `az-sdd/ARCH.md` 获取技术架构
2. 读取 `az-sdd/init.md` 获取项目信息
3. 查找启动/关闭脚本位置

**根据技术架构，检查脚本位置**：

| 技术栈 | 启动脚本 | 关闭方式 |
|--------|---------|---------|
| Python FastAPI + Vue | `code/start.sh` 或 `code/start.bat` | Ctrl+C 或 `code/stop.sh` |
| Python + JSON | `code/run.py` | Ctrl+C |
| 其他 | 根据实际情况确定 | |

### Step 1: 检索待测试功能

```
完成应用启动/关闭测试后，继续执行人工测试。

═══════════════════════════════════════════════════════════════
🧪 人工测试验收


运行脚本生成测试清单页面：

```bash
python az-sdd-test/references/generate-test-review-html.py {项目根目录路径}
```

脚本会自动：
- 扫描所有待测试功能的规范文件
- 提取人工测试用例（MTxxx 格式）
- 生成 `az-sdd-test/references/test-review.html`
- 同时生成 `az-sdd-test/references/test-data.json` 保存测试数据

### Step 3: 主动引导用户

```
═══════════════════════════════════════════════════════════════
🧪 人工测试验收

📋 发现 [N] 个待测试功能，共 [M] 个测试项

─────────────────────────────────────────────────────────────

🎯 请进行测试：

1. 生成测试总览页面（如尚未生成）：
   python az-sdd-test/references/generate-test-review-html.py {项目根目录路径}

2. 双击打开：az-sdd-test/references/test-review.html

3. 点击功能卡片展开测试项

4. 点击测试项标题，用 VSCode 打开规范文件查看测试要求

5. 按要求完成测试后，在页面上勾选测试项

6. 完成所有测试后，关闭浏览器，回复"测试已完成"

─────────────────────────────────────────────────────────────

💡 下一步：
• 测试全部完成后 → 回复"测试已完成"，AI 将检查结果并更新状态
• 查看其他功能 → 在 HTML 页面中切换
```

### test-data.json

```json
{
  "specs": [
    {
      "id": "0001",
      "name": "用户注册",
      "module": "用户模块",
      "status": "待验收",
      "specPath": "/path/to/0001-用户注册.spec.md"
    }
  ],
  "cases": [
    {
      "id": "MT001",
      "title": "界面布局验证",
      "type": "人工",
      "status": "待验证",
      "specId": "0001",
      "specName": "用户注册",
      "specPath": "/path/to/0001-用户注册.spec.md"
    }
  ],
  "generatedAt": "2024-01-15T10:30:00"
}
```

### 状态说明

| 测试项状态 | 含义 |
|-----------|------|
| 待验证 | 未开始测试 |
| 已通过 | 测试通过，已勾选 |
| 失败 | 测试未通过（失败项不允许勾选） |

---

## 错误处理

| 情况 | 处理方式 |
|------|---------|
| 没有待测试功能 | 提示没有需要测试的功能 |
| test-data.json 不存在 | 提示先运行生成脚本 |
| 用户未完成测试就结束 | 页面已有离开提醒，AI 不阻止 |
| 有测试项未勾选 | 询问是确认完成还是返回继续测试 |

## HTML 页面功能说明

`test-review.html` 页面功能：

1. **展示待测试功能列表**
   - 显示所有待测试的功能
   - 显示每个功能的测试项数量和状态

2. **展开/收起测试项**
   - 点击功能卡片展开测试项列表

3. **打开规范文件**
   - 点击测试项标题，用 VSCode 打开规范文件
   - 查看测试要求和操作步骤

4. **勾选测试项**
   - 完成后在页面勾选测试项
   - 勾选状态保存在浏览器 localStorage

5. **离开提醒**
   - 关闭浏览器时提醒还有多少测试项未完成

6. **测试结果持久化**
   - 测试结果保存在 localStorage
   - 刷新页面不会丢失进度
