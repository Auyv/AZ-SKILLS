# AZ-SDD-ARCH

技术规范编写（可选）- 为复杂技术决策创建独立规范。

## 何时使用

```
┌─────────────────────────────────────────────────────────┐
│                    决策流程                              │
│                                                         │
│  新功能需要技术规范？                                     │
│         │                                                │
│         ├─► 简单功能，无复杂技术决策                      │
│         │         │                                      │
│         │         └─► 不需要！技术约束已在 spec 中        │
│         │                                                │
│         └─► 复杂功能，涉及以下情况 ──► 使用 az-sdd-arch   │
│                      │                                   │
│                      ├─► 多个模块/子系统交互              │
│                      ├─► 架构变更或重构                   │
│                      ├─► 新技术/框架引入                  │
│                      ├─► 详细技术选型对比                │
│                      └─► 重要数据模型设计                │
└─────────────────────────────────────────────────────────┘
```

## 执行步骤

### Step 1: 检查环境

```
1. 检查 az-sdd/ 目录是否存在
   → 不存在：提示先执行 /az-sdd-init
   → 存在：继续
2. 读取对应的功能规范（spec）
   → 确认功能需求和业务约束
3. 检查 .config/naming.yaml 获取编号规则
```

### Step 2: 分析技术复杂度

从功能规范中提取技术相关要素：

```
📋 从功能规范提取的技术信息：

| 要素 | 内容 |
|------|------|
| 数据存储需求 | {STORAGE} |
| 用户认证需求 | {AUTH} |
| 外部接口 | {EXTERNAL_API} |
| 性能要求 | {PERFORMANCE} |
| 特殊要求 | {SPECIAL} |

🤔 技术复杂度评估：
- 模块数量：{N}
- 外部依赖：{M}
- 技术风险：{RISK}

建议：{SUGGESTION}
```

### Step 3: 判断是否需要独立技术规范

**如果判定为简单功能**：
```
💡 这个功能比较简单，技术约束已包含在功能规范中。
   无需创建独立的技术规范文档。

   如有需要，可随时使用此 SKILL 创建独立技术规范。
```

**如果判定为复杂功能**：
```
📝 检测到此功能涉及复杂技术决策，建议创建独立技术规范。

需要处理的技术议题：
1. {TOPIC_1}
2. {TOPIC_2}
3. {TOPIC_3}

是否继续？
- [继续] 创建技术规范
- [跳过] 保持现状，技术约束在 spec 中
```

### Step 4: 收集技术信息

**必须询问用户**：

1. **涉及哪些技术组件？** - 前端、后端、数据库、外部服务？
2. **技术选型有没有偏好？** - 有没有想用的框架或工具？
3. **有没有技术限制？** - 如：必须用某数据库、不能引入某依赖？
4. **性能要求是什么？** - 响应时间、并发量、数据量？

### Step 5: 生成规范

```
文件：az-sdd/arch/{ID}-{MODULE}-{NAME}.arch.md
```

### Step 6: 更新索引

更新 `az-sdd/ARCH.md` 中的技术规范列表。

### Step 7: 输出结果

```
✅ 技术规范已创建！

📄 文件：az-sdd/arch/{ID}-{MODULE}-{NAME}.arch.md

🔑 关键技术决策：
1. {DECISION_1}
2. {DECISION_2}

📊 涉及组件：
- {COMPONENT_1}
- {COMPONENT_2}

💡 下一步：
1. /az-sdd-coding 开始代码实现
2. /az-sdd-spec 查看功能规范
```

## 错误处理

| 情况 | 处理方式 |
|------|---------|
| az-sdd/ 不存在 | 提示先执行 /az-sdd-init |
| 对应 spec 不存在 | 提示先创建功能规范 |
| 功能较简单 | 建议跳过，保持 spec 中的技术约束 |
| 许可证风险 | 必须提示用户，等待确认 |
