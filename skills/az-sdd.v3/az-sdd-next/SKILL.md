# AZ-SDD-NEXT

流程导航器 - 读取项目状态，引导用户执行下一步工作。

## 核心能力

```
┌─────────────────────────────────────────────────────────────┐
│                      az-sdd-next                           │
├─────────────────────────────────────────────────────────────┤
│  读取状态 → 分析阶段 → 推荐技能 → 生成提示词                   │
│                                                              │
│  用户只需：复制提示词 → 粘贴给 AI → 继续开发                   │
└─────────────────────────────────────────────────────────────┘
```

## 执行步骤

### Step 1: 读取项目状态

按顺序检查以下文件，获取项目全景：

```
1. az-sdd/SPEC.md
   → 获取：所有功能列表、编号、状态

2. az-sdd/ARCH.md（如存在）
   → 获取：技术架构、已定版的技术方案

3. az-sdd/track.md（如存在）
   → 获取：当前工作重点、阻塞项、待处理项

4. az-sdd/spec/ 目录下的 .spec.md 文件
   → 读取各功能规范详情，了解具体进展
```

### Step 2: 分析当前阶段

根据 SPEC.md 中各功能的状态，判断项目整体阶段：

```
项目阶段判断规则：

【初始化阶段】
  所有功能状态 = 空 或 草稿
  → 当前：无规范，进入 spec 阶段

【规范阶段】
  部分功能状态 = 草稿/审核中
  → 当前：还有规范待编写或审核

【待开发阶段】
  存在功能状态 = 已批准（但未开始开发）
  → 当前：有已批准的规范，可以开始 coding

【开发阶段】
  存在功能状态 = 开发中 或 测试中
  → 当前：有功能正在进行开发或测试

【验收阶段】
  存在功能状态 = 待验收
  → 当前：有功能等待用户确认验收

【全部完成】
  所有功能状态 = 已完成/已发布
  → 当前：项目告一段落，可以规划新功能或收尾

【混合阶段】（最常见）
  多个功能处于不同状态
  → 当前：需要选择优先处理哪个
```

```
│                                                              │

│     🔄 开发中：1 个                                           │
│     ⏳ 待开发：3 个                                           │
│     📝 规范中：1 个                                           │
│                                                              │
│  🎯 当前工作：                                                │
│     [0003] 任务列表功能 - 开发中                              │
│                                                              │

```

### Step 4: 生成提示词（核心输出）

根据分析结果，生成用户可以直接复制使用的提示词。

---

#### 场景 A：项目未初始化

```
💡 检测到尚未初始化 AZ-SDD 项目。

📝 复制以下提示词开始：

---
请帮我初始化 AZ-SDD 项目。

项目名称：{项目名称}
项目描述：{一句话描述项目做什么}
项目类型：个人项目 / 团队协作 / 其他
---

复制 → 粘贴给 AI → 开始
```

---

#### 场景 B：有功能待编写规范

```

我有以下需求需要实现：

```

### Step 5: 持续引导

在用户完成当前操作后，自动在响应末尾添加导航提示：

```
──────────────────────────────────────────────────────────────

📍 你目前的位置：【开发阶段】

💡 建议操作：
   • 继续开发 [0003] → 复制上方提示词
   • 查看项目进度 → /az-sdd-track
   • 遇到问题反馈 → /az-sdd-feedback

──────────────────────────────────────────────────────────────
```

## 提示词模板库

系统内置常用场景的提示词模板：

### 模板 1：继续开发

```
请继续开发 [功能编号] [功能名称] 功能。

当前状态：[从规范中读取]
已完成：[已完成的部分]
待完成：[待完成的部分]

请按规范要求继续实现。
```

### 模板 2：开始新功能

```
请开始实现 [功能编号] [功能名称] 功能。

功能规范：az-sdd/spec/[编号]-[名称].spec.md
技术架构：az-sdd/ARCH.md

请先阅读规范，确认理解后开始编码。
```

### 模板 3：修复问题

```
请帮我排查和修复以下问题：

问题描述：[用户描述]
相关功能：[功能编号]
相关规范：[规范路径]

请先分析可能的原因，再进行修复。
```

### 模板 4：添加新功能

```
请帮我添加一个新功能。

功能需求：[用户描述]

请使用 /az-sdd-spec 创建规范。
```

### 模板 5：查看进度

```
请帮我查看当前项目进度。

使用 /az-sdd-track 命令查看详细状态。
```

## 状态速查表

| 当前状态 | 用户想做什么 | 推荐操作 |
|---------|-------------|---------|
| 项目未初始化 | 开始新项目 | 模板1：初始化 |
| 有草稿/审核中规范 | 继续写规范 | 模板4：添加功能 |
| 有已批准规范 | 开始开发 | 模板2：开始新功能 |
| 开发中 | 继续编码 | 模板1：继续开发 |
| 测试中 | 完成测试 | 模板X：进行测试 |
| 待验收 | 确认完成 | 模板X：验收确认 |
| 全部完成 | 看进度/加功能 | 查看进度/添加功能 |

---

## 错误处理

| 情况 | 处理方式 |
|------|---------|
| az-sdd/ 目录不存在 | 提示先初始化：模板1：初始化 |
| 无法读取 SPEC.md | 提示项目可能已损坏或未正确初始化 |
| 状态判断不明确 | 显示所有可能选项，让用户选择 |
| 用户选择与推荐不符 | 尊重用户选择，更新上下文 |
