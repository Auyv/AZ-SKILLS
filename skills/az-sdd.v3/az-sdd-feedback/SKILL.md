# AZ-SDD-FEEDBACK

智能反馈处理 - 自动分类用户反馈，触发对应处理流程，全程可追溯。

## 日常使用边界

- 仅在用户要求把反馈纳入 AZ-SDD，或当前项目已使用 `az-sdd/` 档案时创建反馈单。
- 普通 bug 修复优先直接定位和修复；需要追溯、复盘或用户验收时再进入 feedback 流程。
- 反馈闭环的目标是产生下一步行动：修复、修改 spec、创建新 spec，或明确关闭原因。

## 核心理念

```
┌─────────────────────────────────────────────────────────────┐
│  面向用户 ≠ 面向规范                                         │
├─────────────────────────────────────────────────────────────┤
│  用户只需描述问题和期望，AI 自动处理技术细节                  │
│                                                              │
│  Bug 报告 ──────────→ 自动修复（Coding）                     │
│  改进建议 ─────────→ 确认需求变更 → 规范更新（Spec）         │
│  新功能需求 ────────→ 规范创建（Spec）                       │
└─────────────────────────────────────────────────────────────┘
```

## 执行步骤

### Step 1: 收集用户反馈

### Step 1.1: 识别反馈意图

```
用户输入：{用户的原始描述}

AI 自动识别反馈类型：

┌─────────────────────────────────────────────────────────────┐
│ 🤔 反馈类型识别                                              │
├─────────────────────────────────────────────────────────────┤
│ 您的反馈是以下哪种情况？                                      │
│                                                             │
│  🐛 Bug - 系统出现异常或错误                                  │
│     例如：点击没反应、内容显示错误、功能无法正常使用            │
│                                                             │
│  💡 改进建议 - 现有功能太复杂，想简化                         │
│     例如：操作步骤太多、界面不够直观、想减少点击次数           │
│                                                             │
│  ✨ 新功能需求 - 希望增加新功能                               │
│     例如：想要批量操作、想要导出功能、想要新模块               │
└─────────────────────────────────────────────────────────────┘

请选择：1（Bug）/ 2（改进建议）/ 3（新功能）/ 或直接描述您的问题
```

### Step 1.2: 收集反馈信息

**对于所有类型，必须收集**：

```
1. 问题描述（用户用自己的语言描述）
2. 发生场景（在什么情况下出现问题）
3. 期望行为（用户希望应该如何）
4. 反馈时间
5. 反馈来源
```

**面向用户的提问方式**（不需要技术术语）：

```
🐛 Bug 反馈收集：

请描述一下遇到的问题：

1. 【问题】具体是什么不对劲？
   例如：输入框里无法输入文字

2. 【场景】在什么情况下出现的？
   例如：在填写表单的时候

3. 【期望】您觉得应该是什么样的？
   例如：应该能正常输入才对

4. 【影响】这个问题严重吗？
   • 🔴 很严重，完全无法使用
   • 🟡 有些麻烦，但还能用
   • 🟢 不太影响使用
```

## 状态定义

| 状态 | 颜色 | 说明 |
|------|------|------|
| 待处理 | 🔴 红色 | 新反馈，未分析 |
| 分析中 | 🟡 黄色 | 正在分析问题 |
| 处理中 | 🔵 蓝色 | 正在修复/实现 |
| 待验证 | 🟠 橙色 | 等待用户验证 |
| 已解决 | 🟢 绿色 | 问题已修复/建议已采纳 |
| 已关闭 | ⚪ 灰色 | 不采纳/无法复现 |

## 错误处理

| 情况 | 处理方式 |
|------|---------|
| az-sdd/ 不存在 | 创建基础目录结构 |
| 反馈内容不明确 | 用通俗语言引导用户描述 |
| Bug 无法定位 | 询问更多细节，尝试复现 |
| 改进建议涉及多个规范 | 逐一处理或合并处理 |
| 新功能与其他需求冲突 | 记录冲突，等待评估 |

---

## 反馈单命名规范

```
az-sdd/feedback/
├── bugs/
│   └── BUG-{YYYY}-{SEQ}.bug.md           # Bug 反馈单
├── improvements/
│   └── IMP-{YYYY}-{SEQ}.improve.md       # 改进建议单
├── requests/
│   └── REQ-{YYYY}-{SEQ}.request.md       # 新功能需求单
├── reports/
│   └── {YYYY}-{MM}-report.html           # 月度反馈报告
└── FEEDBACK.md                           # 反馈索引
```

## 与其他 SKILL 的联动

```
用户提交反馈
     │
     ├── Bug ──────────→ /az-sdd-coding ──→ 修复 ──→ 验证 ──→ 关闭
     │
     ├── 改进建议 ──────→ 检查规范 ──→ 解释设计
     │                              │
     │                              ├── 用户接受 ──→ 关闭
     │                              │
     │                              └── 用户要求变更 ──→ /az-sdd-spec ──→ 更新规范
     │
     └── 新功能需求 ─────→ 检查规范
                              │
                              ├── 存在类似 ──→ 询问差异
                              │
                              └── 不存在 ──→ /az-sdd-spec ──→ 新增规范
```
