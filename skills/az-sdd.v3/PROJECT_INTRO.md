# AZ-SDD v3 — 规范驱动开发智能助手

AZ-SDD 是一套面向 AI 编程助手的日常开发工作流。它把需求、规范、实现、测试、验收、进度和反馈沉淀为项目档案，帮助用户从“临时让 AI 改代码”升级为“可追踪、可验收、可持续迭代”的开发方式。

## 产品定位

AZ-SDD 不承诺 AI 自动完成所有软件开发。它解决的是更实际的问题：

- 需求描述容易变形。
- AI 多轮修改后上下文丢失。
- 开发完成后缺少验收证据。
- 用户反馈没有进入下一轮规范。
- 个人和小团队缺少轻量项目治理工具。

## 本次最终提交

本次提交版本为 `skills/az-sdd.v3`，包含 9 个子 skill、规则配置、安装脚本、使用文档和比赛表单填写稿。

配套应用案例为 `skill商店`，案例目标是公司内部 Skill 共享平台。该案例保留原始项目文档，并通过 AZ-SDD 档案沉淀 13 个功能规范、项目状态追踪、coding 计划、人工测试工单和 Docker 部署材料，展示从需求到工程骨架再到验收档案的完整闭环。

## 核心设计

| 设计 | 实际价值 |
|------|----------|
| spec 先行 | 开发前明确范围、验收标准和技术约束 |
| 状态机 | 避免“做到哪了”只能靠聊天记录猜 |
| 测试工单 | 把人工验收过程结构化、可归档 |
| feedback 闭环 | 将 bug、建议、新需求转成下一步行动 |
| next 入口 | 用户不用记完整流程，由 AI 读取状态后推荐下一步 |
| rules 检查 | 用明确清单约束流程，不依赖平台级 hook |

## Skill 体系

AZ-SDD v3 包含 9 个模块：

| Skill | 角色 |
|-------|------|
| az-sdd-next | 日常主入口，读取项目状态并推荐下一步 |
| az-sdd-init | 初始化档案目录 |
| az-sdd-spec | 生成或修改功能规范 |
| az-sdd-arch | 处理复杂技术决策 |
| az-sdd-coding | 按规范编码，支持批量开发计划 |
| az-sdd-test | 组织测试与人工验收 |
| az-sdd-track | 查看和更新进度 |
| az-sdd-feedback | 处理用户反馈 |
| az-sdd-rules | 提供规则、状态机和前置检查 |

## 使用模式

| 模式 | 适合任务 | 特点 |
|------|----------|------|
| lite | 小改动、低风险功能 | 少文档，保留最小 spec 和 checklist |
| standard | 日常功能开发 | 默认模式，覆盖规范、编码、测试、追踪 |
| strict | 多模块或交付型功能 | 增加 arch、签名验收、反馈追溯 |

## 关键边界

- 普通“写代码”“跑测试”“修 bug”不应自动触发 AZ-SDD。
- 只有用户明确提到 AZ-SDD/SDD、使用 `/az-sdd-*` 命令，或要求“按规范流程”时才进入该体系。
- `az-sdd-rules` 不假设平台一定支持自动 hook；实际执行时由 `/az-sdd-next` 或各 skill 显式做前置检查。

## 适用场景

- 个人项目从想法到可运行功能。
- 小团队用 AI 做功能迭代，需要轻量规范和验收。
- 产品/运营/非技术用户参与需求和验收。
- AI 编程培训、工作坊和团队方法论落地。

## 不适用场景

- 大型企业已具备成熟需求、研发、测试、发布工具链，且不希望引入额外档案。
- 高安全/高合规项目尚未做权限、审计、CI、工单系统集成。
- 临时实验代码，不需要任何状态记录。
