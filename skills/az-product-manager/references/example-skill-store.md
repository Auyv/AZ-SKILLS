# az-product-manager Skill 使用示例

> **目的**：展示 az-product-manager skill 的完整使用流程
> **来源**：从 skill 商店项目的真实对话中提炼

---

## 第 1 轮：听用户说

**用户**：我想做一个 skill 商店，方便公司内部人员分享 skill。所有人上传的 skill 可以一键生成安装命令，便于同事的使用。

**AI 回应**：
```
收到！skill 商店——公司内部 AI 技能共享平台。

先问 3 个关键问题：
1. 这个商店部署在哪？公司内网服务器 / 你的办公电脑 / 云？
2. 大概多少人同时用？
3. 是所有同事都能上传，还是只有指定的人能？

另外我再想到 2 个：
4. 用什么方式登录？工号 / 邮箱 / 第三方？
5. 需不需要审核？有人上传的 skill 不一定靠谱
```

---

## 第 2 轮：澄清背景

**用户**：就是公司内部用，目前就想到这些。

**AI 回应**：
```
好的，内部用。再问 2 个：
1. 现在同事之间是怎么分享 skill 的？群里发文件？U盘拷？
2. 为什么现在想做？是因为每次新人入职都要一个个教？
3. 做完之后最理想的状态是什么？（一句话描述）
```

**用户**：
1. 现在就是群里发文件
2. 是的，每次新人来都要教，烦
3. 我希望新人入职打开一个网页，就能看到所有能用的 skill，复制一条命令就装好了

---

## 第 3 轮：明确用户

**AI 回应**：
```
明白了！那么这 4 件事：

1. 大概多少人用？10 个？50 个？500 个？
2. 他们在哪用？办公室电脑？出差路上？
3. 要不要手机上能用？
4. 有没有现成的"花名册"——同事信息从哪来？
```

**用户**：20 个人左右，都在办公室用，Win 电脑。手机上能看就行，主要还是电脑用。

---

## 第 4 轮：勾勒功能

**AI 回应**：
```
好，我整理一下你提到的功能 + 我想到的你可能漏掉的：

【你提到的】
  1. 上传 skill
  2. 浏览 skill
  3. 一键生成安装命令

【我补充的】
  4. 登录：得知道谁上传了谁
  5. 审核：上传的 skill 不一定靠谱，得有人过一眼
  6. 分类：skill 多了得分类，否则翻不到
  7. 搜索/筛选：20 个 skill 也要搜
  8. 积分系统：上传有奖励，下载有消耗，避免滥用

你要加哪些？哪些不要？
```

**用户**：审核要有！其他都加。

---

## 第 5 轮：关键决策（3 选 1）

**AI 展示决策表**（典型示例）：

```
关于【部署位置】：

| 方案 | 一句话 | 适合场景 | 推荐 |
|---|---|---|---|
| A. 你的办公电脑 | 你这台装个服务，同事访问 | 小团队 | ⭐⭐⭐⭐⭐ |
| B. 公司服务器 | 找 IT 申请一台 | 长期项目 | ⭐⭐⭐ |
| C. 云服务 | 阿里云/AWS | 跨地域 | ⭐⭐ |

关于【登录方式】：

| 方案 | 一句话 | 适合场景 | 推荐 |
|---|---|---|---|
| A. 工号 + 密码 | 大家都用 4 位工号 | 内部系统 | ⭐⭐⭐⭐⭐ |
| B. 邮箱 + 密码 | 通用 | 对外 | ⭐⭐⭐ |
| C. 接入企业 SSO | 走公司账号 | 大企业 | ⭐⭐ |

关于【积分规则】：

| 方案 | 初始 | 上传 | 下载 |
|---|---|---|---|
| A. 简单 | 3 | +5 | -1 |
| B. 严苛 | 1 | +10 | -2 |
| C. 宽松 | 10 | +2 | -1 |

你选哪几个？
```

**用户**：A + A + A，按你的推荐来。

## 第 6 轮：风险识别

**AI 主动提**：

```
我想到了 5 个将来可能踩的坑：

🔴 必须解决（不做就出事）：
  R1. 上传恶意文件——有人可能上传带病毒的 zip
  R2. 暴力破解密码——123456 太容易试
  R3. 积分被刷——有人会钻空子

🟡 应该解决（做了更稳）：
  R4. 服务器断电丢数据
  R5. WSL2 关了服务就停

🟢 知道就行（v1 不用做）：
  R6. 浏览器兼容（用 IE 的人）
```

---

## 第 7 轮：交付派工包

**AI 交付**：

```
🎉 派工包已完成！6 份文档已生成。

📂 位置：项目集/skill商店/01-规范/

📋 文档清单：
  1. README.md（项目总览）
  2. spec-功能规范.md（业务需求）
  3. arch-技术架构.md（技术 + 15 个风险）
  4. api-接口契约.md（26 个 API）
  5. task-开发任务拆单.md（10 个工单）
  6. test-验收用例.md（150+ 用例 + 5 端到端场景）

💼 你的下一步：
  1. 找开发（一个后端 + 一个前端）
  2. 把整个文件夹发给 ta
  3. 按 task 文档派工
  4. 开发有疑问找我（不写代码，但可讲解）
  5. 交付后用 test 文档验收
```

---

## 💡 这个示例的关键点

### 1. 7 轮对话结构清晰
- 每轮只问 1-3 个问题
- 每轮有明确产出（写进文档）

### 2. 用了大量比喻
- 部署机 = "办公电脑"（不叫"WSL2"）
- 登录 = "知道谁"（不叫"鉴权"）
- 审核 = "过一眼"（不叫"审批流"）

### 3. 主动提用户没想到的
- 用户只说"上传+浏览+下载"
- AI 补充了：审核、分类、搜索、积分

### 4. 3 选 1 拍板
- 部署 / 登录 / 积分 都给了表格
- 用户不需要写文字，点 A/B/C 就行

### 5. 风险主动识别
- 5 个风险被识别出来
- 分级 🔴/🟡/🟢

### 6. 边界感强
- 全程 AI 没写一行代码
- 全程 AI 没装一个软件
- 全程 AI 没替用户拍板
- 决策都让用户确认
