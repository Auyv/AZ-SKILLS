# az-api-summary 异常处理 FAQ

## 1. 输出有 API 清单，但初学者仍看不懂

**现象**：文档直接使用 APDU、SCP02、MAC、CBC、ZA、`key_id` 等术语，没有解释上下文。

**原因**：只按厂商文档目录整理接口，遗漏了读者知识背景。

**处理**：

1. 把术语表放在正文前部，而不是文末附录。
2. 先增加“容易混淆的概念”对照表。
3. 每个术语同时写英文全称和在当前 SDK 中的实际含义。
4. 至少解释加密/签名、HASH/MAC、`key_id`/`session_id`、会话密钥/业务会话的区别。
5. 只解释正文实际出现的算法，不堆砌无关密码学知识。

## 2. CHM 解包后中文乱码

优先按 UTF-8 读取 Doxygen HTML。若仍乱码，检测页面 meta、UTF-8、GBK 和 GB2312；不要把终端默认编码当成文件编码。

## 3. Doxygen 分组页没有函数

部分 CHM 的 `Exported Functions` 分组为空，但头文件参考页或 `*_source.html` 有声明。合并扫描以下来源：

- `group_*_exported_functions.html`
- `*_8h.html`
- `*_source.html`
- 宏定义，例如 `api_register` 可能封装内部 `_api_register`

## 4. PDF 文本提取把表格列打乱

渲染代表页面，按视觉顺序重建表格。流程图必须检查箭头方向和判断分支，不能仅依赖抽取文本。

## 5. 不知道接口应该归到哪一层

按以下证据强弱排序：文档明确分层、模块父子关系、源码目录、函数前缀、调用引用。无法确认时标记为推断。

## 6. SDK 有接口，但项目明确不实现

保留在“SDK 全量能力”清单中，在“项目能力映射”中标记为当前不开放。不要因为厂商 SDK 存在接口就扩大项目范围。

## 7. 文档中找不到同名业务接口

例如需求是“公钥导入”，CHM 可能没有 `api_import_public_key`。列出最接近的密钥写入/装载接口和待确认的数据格式，但不要凭函数名直接认定映射关系。

## 8. 输出文件已存在

默认返回 `ERR_OUTPUT_EXISTS`。只有用户明确允许覆盖时才继续，并先识别编码、读取目标和备份到 `.ai_tmp/bak/`。
