# AI 工作交接工作流

把进行中的任务从一个 Agent/工具交给另一个 Agent/工具继续。工作流分为交出方和接收方两个角色流程，共用一个交接文档协议：交出方记录目标、进展和上下文；接收方先读文档并核对现场，有疑问时通过可用渠道询问交出方，答复回写文档后再继续。

## 输入与边界

技能调用支持自然语言参数或 `key=value` 参数。参数有值时按原值执行，不要自行替换；缺失时按“缺省行为”处理，只有会影响目标、文档读写或交接对象的信息无法推断时才提问。

| 参数 | 含义 | 缺省行为 |
| --- | --- | --- |
| `mode` | `handoff` 交出，或 `receive` 接收 | 根据用户请求判断；无法判断时问一次 |
| `agent` | 当前调用方的 Agent/工具身份，例如 `Codex`、`Claude Code`、`OpenCode` | 使用运行环境可确认的名称；无法确认时写“未指定”，不得猜测 |
| `peer` | 对端 Agent/工具身份 | 未知时写“待指定”；不阻止生成文档 |
| `document` | 交接文档绝对路径；`handoff` 时是输出路径，`receive` 时是输入路径 | `handoff` 使用默认临时路径；`receive` 从用户附带文件或上下文定位，找不到时询问 |
| `task` | 任务短名称，用于默认文件名和文档标题 | 从当前任务生成简短名称 |

示例调用：

```text
$az-ai-handover-workflow mode=handoff agent=Codex peer=Claude document="C:\HQ_Workspace\project\.ai_tmp\handoffs\HJ1239测试.md" task=HJ1239测试
$az-ai-handover-workflow mode=receive agent=Claude peer=Codex document="C:\HQ_Workspace\project\.ai_tmp\handoffs\HJ1239测试.md"
```

也可以用自然语言传参，例如：“调用交接技能，我是 Codex，交给 Claude，文档输出到 `C:\...\handoff.md`。”

硬边界：

- **不得写入凭据、token、密码、私钥、内网敏感地址等秘密信息**；发现交接内容涉及秘密时停止并交由用户当面传递。
- 交接文档不是仓库交付物，不得提交到 git；写入前确认目标目录的忽略状态。
- 交出方等待接收方澄清期间，不继续改动已交出的任务，除非用户另行指示；接收方可继续不依赖答案的只读核对。

## 共用规则

- 默认文档路径为当前工作区 `.ai_tmp/handoffs/<任务标识>.md`。用户指定路径时使用指定路径。跨主机或工具时，先确认接收方能访问该路径；不能访问时，由用户将文档复制、附加或放入双方可访问的位置。
- 文件名使用短任务名和日期，避免覆盖已有交接。文档开头写状态：`待接收`、`待澄清`、`已接手`、`已完成`。
- `handoff` 模式下文档交出方填写 `agent`、接收方填写 `peer`；`receive` 模式保留文档原有身份，只在问答记录中用当前调用参数 `agent` 标记发言者。参数未提供的身份如实标为“未指定”或“待指定”。
- 状态按生命周期更新：交出方创建时为 `待接收`；接收方存在关键问题时改为 `待澄清`；接收方确认理解并开始继续时改为 `已接手`；用户目标完成时改为 `已完成`。
- 只写接手所需上下文，不写 token、密码、私钥或其他凭据。保留排障所需的非秘密地址、命令、日志和设备信息；遵守项目对敏感信息的额外规则。
- 区分已验证事实、推断、假设和待确认问题。文档中的命令应标出是否已执行及结果，不能把建议命令写成已完成操作。
- 交接文档是临时协作材料，不提交到产品代码仓库。优先放在已忽略的临时目录；若目录未忽略，使用本地 Git exclude 或工作区外路径，不能为此修改项目 `.gitignore`。
- 不因交接而扩大授权。接收方沿用原任务中仍有效的用户授权；新出现的高风险、外部写入或不可逆动作仍按原规则处理。

## 角色流程

### A. 交出方：整理并交接

1. 汇总本轮仍未完成的用户目标、已完成工作、当前阻塞、下一步和成功判定。阅读必要的 `AGENTS.md`、项目规则和相关技能，避免遗漏仍有效的用户授权与限制。
2. 将 `document` 作为输出路径；未提供时生成 `<工作区>/.ai_tmp/handoffs/<task>-<日期>.md`。创建前检查目标文件是否已存在；若存在，不覆盖，改用新文件名或请用户指定后再继续。复制 [`templates/handover-template.md`](templates/handover-template.md) 创建临时交接文档，并写入 `agent`、`peer` 身份。按任务裁剪模板，不保留空章节：
   - **任务目标与完成标准**：用户原始目标、范围和可观察的验收条件。
   - **当前进展**：已经完成、尚未完成、明确失败或未验证的事项。
   - **必要上下文**：项目/工作区绝对路径、仓库与分支/HEAD（适用时）、设备/服务状态、关键配置与构建环境。
   - **关键文件和证据**：绝对路径及行号、报告/日志路径、命令和实际输出；区分事实与推断。
   - **授权与约束**：用户明确允许/禁止的操作、必须遵守的规则、仍有效的风险门槛。
   - **待办和判定方法**：按顺序给出可执行步骤、预期结果及失败时检查的证据。
   - **待澄清问题**：只列会改变范围、根因判断、方案或验收结果的问题。
   - **交接状态和更新时间**。
3. 生成用户可复制给接收方的启动文本，包含文档绝对路径、不可访问时的处理方式、当前有效授权与限制；要求接收方完整阅读、核对状态、复述目标与进展，并按下文 B 流程处理问题。没有实质疑问且原授权仍适用时，接收方可以继续，不必等待重复确认。
4. 告知用户文档位置和启动文本。若接收方尚未确认可访问，不要声称交接已完成。

### B. 接收方：阅读、核对、提问并继续

1. 将 `document` 作为输入路径；未提供时从用户附加文件或明确上下文中定位。完整读取交接文档，再读取文档指向的规则和关键证据。先确认路径可访问；不可访问时，请用户提供文件或共享位置，不要凭启动提示重建上下文。
2. 对高影响状态做只读核对，例如当前分支/HEAD、文件差异、设备连接和服务状态。区分文档记录的历史状态与此刻状态；文档与现场不同时，以现场为准并通知交出方。
3. 形成简短接手确认：复述目标、当前状态、下一步和验收标准。若没有实质疑问且用户先前授权仍适用，可以继续执行，不需要为确认而重复询问用户。
4. 若疑问会影响目标、实现选择、设备状态或验收，暂停依赖该信息的动作，按以下格式提问。独立且不依赖答案的只读检查可以继续。

```
【交接问题 N】<简短标题>
- 文档依据：<路径/章节或 file_path:line_number>
- 已核实事实：<当前可证实的信息>
- 待确认：<一个具体问题>
- 影响：<缺少答案会改变什么>
- 建议：<可选建议及理由；没有把握时省略>
```

5. 在同一会话可直接联系交出方且用户已授权该沟通时，直接询问；否则将问题交给用户转达。不得默认有权限向其他会话、Agent 或人员发送消息。
6. 交出方答复后，把答案、`agent` 身份和时间追加到交接文档的“问答记录”，并将状态更新为 `待接收` 或 `已接手`。接收方重新读取更新内容，确认疑问已解决，再继续任务。
7. 接收方完成用户目标后，更新任务结果和验证证据，再按清理约定处理临时文档。接收方不要在仍有待答问题时删除文档。

### C. 问答与清理约定

- 交出方看到转述的问题后，直接给出事实、限制和答案；有必要时更新交接文档，不要求接收方重复问已经回答的内容。
- 问答结论影响任务范围、配置或实施选择时，必须回写临时文档，避免答案只留在用户转述消息中。
- 临时文档在接收方确认完成接手、所有关键疑问已解决且继续任务所需信息已纳入当前会话后，由接收方删除。若工作需要长期留存，将结论转入正式文档、MR 或问题单，再删除临时文档。
- 删除前检查路径和文件名，避免删除同目录下的其他交接资料。不得提交该临时文档。

## 交付检查

生成后逐项自检：

- 交接文档路径可访问，或明确说明如何交给接收方；启动文本携带准确路径。
- 文档清楚写出任务目标、进展、未完成项、授权约束、证据和下一步；事实、推断、假设没有混写。
- 全文无凭据类敏感信息，无未替换的占位符。
- 待办可执行，命令、报告和关键文件路径准确；未执行的操作没有写成已完成。
- 文档位于忽略路径或工作区外，不污染产品仓库状态。
- 接收方已复述目标和状态；如有关键疑问，已通过问答记录闭环。

## 停止条件

出现以下情况时停止并报告事实与所需决定，不得猜测继续：

- 接收方无法访问交接文档且用户尚未提供可访问副本。
- 交接内容涉及凭据、密钥或敏感地址。
- 目标路径不可写，或写入会覆盖已有且来源不明的同名文档。
- 接收方遇到会实质改变范围、风险或验收标准的问题，且交出方/用户尚未答复；暂停依赖该答案的动作。
