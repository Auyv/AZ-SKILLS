# 自适应技能创建示例

仅在需要理解快速模式与工程化模式差异时阅读本文件。

## 快速模式：Markdown 标题评审

用户请求：

> 创建一个技能，在用户要求检查 Markdown 标题层级时输出问题清单。

合理交付：

```text
az-markdown-heading-review/
└── SKILL.md
```

`SKILL.md` 应包含准确的触发描述、标题层级检查规则、输出要求和边界。不需要为简单文本判断创建 Python 脚本、`MANUAL.md`、通用错误码或空目录。

## 工程化模式：批量日志解析

用户请求：

> 创建一个跨平台技能，批量解析目录中的设备日志并生成 JSON 汇总，要求严格测试。

合理交付可能是：

```text
az-device-log-summary/
├── SKILL.md
├── scripts/
│   └── summarize_logs.py
└── evals/
    └── evals.json
```

设计要点：

- Agent 判断日志类型、输入范围和用户意图，并在路径或覆盖权限不明确时集中确认。
- Python 使用标准库完成遍历、稳定解析、聚合和 JSON 输出。
- 测试覆盖正常目录、空目录、损坏日志、编码差异、无权限文件和输出冲突。
- 只有用户需要脱离 Agent 手工执行时才增加 `MANUAL.md`。
- 只有第三方库带来不可替代价值时才引入，并记录降级方案。

## 发布阶段

以上两种模式完成源码后都默认停止。用户明确要求发布到目标 Agent 时，再登记 `manifest.yaml`，运行 dry-run、正式同步和目标验证。
