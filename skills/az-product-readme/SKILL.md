# 产品化 README 写作标准

## 做什么

为可交付工具写出让首次用户一眼理解价值、能立即执行、遇到异常也知道下一步的 README。默认面向工具使用者，不把源码结构、内部文件名、解析算法等实现细节放在主路径中。

## 何时使用

- 用户说“写 README”“完善使用说明”“准备正式发布”“让文档更吸引人”。
- 已有 README 偏开发者视角，缺少效果图、上手路径、输出解释或异常处理说明。
- 新增 GUI、命令行、报告、风险定位、CI 退出码或发布包后需要同步文档。

## 工作原则

1. 先验证事实，再写文档。命令、文件名、运行前置条件、输出路径和退出码必须来自实际产物或代码。
2. 从用户任务组织内容：用户输入什么、点击或执行什么、看到什么、异常时怎么做。
3. 首屏必须让人看懂“这是做什么的”。优先使用真实流程图、GUI、终端或报告截图；有连续操作时可使用轻量 GIF。
4. 流程描述优先画图。架构总览、变更生命周期、状态机等内容用 SVG 图片展示，文字解释放在图片之后；README 中不保留与图重复的 ASCII 流程。
5. 主文档不展开底层实现。除非用户明确需要，否则不要求用户手工处理内部构建制品、调用图、映射文件或配置细节。
6. 结论和风险必须可读。明确区分“工具执行失败”和“扫描完成但发现风险”；使用颜色只能增强信息，不能代替文字。
7. 只描述当前版本实际支持范围；未来方向放在边界说明中，不写成已支持能力。

## 标准流程

### 1. 盘点并验证

读取 README、入口脚本、发布目录和现有图片。确认以下事实：

- 目标用户和核心价值。
- 当前支持的平台、工程类型和前置条件。
- 用户唯一需要提供的输入。
- GUI 和 CLI 的真实入口。
- 默认输出位置、报告类型、退出码和异常含义。
- 是否存在可重用的真实 GUI、报告或终端截图。

修改前识别 Markdown 编码并备份。图片或报告名称变更时，同步检查 README 引用。

### 2. 使用推荐章节顺序

按产品复杂度裁剪，但优先保留以下顺序：

1. 标题、适用对象、当前支持范围和一句话价值。
2. 首屏真实视觉：流程图、报告截图或 GUI GIF。
3. `30 秒开始`：最多四步，推荐默认入口；连续界面操作优先配 GIF。
4. 产品是什么与功能一览：以“用户得到什么”描述，不罗列内部模块。
5. 快速上手：前置条件、唯一输入、GUI 与 CLI 两种路径。
6. 执行后可以得到什么：输出位置、HTML/CSV/JSON 等结果用途和真实截图。
7. 发现异常后如何定位：用一条真实风险记录串联“发现 → 展开详情 → 定位 → 修复后复扫”。
8. 如何理解检查结果：每种状态、退出码、`REVIEW` 原因与建议动作。
9. CI 最小集成：仅给可复制的最小命令与退出码处理，不展开平台实现细节。
10. 推荐现场流程、FAQ 和当前版本边界。

### 3. 设计视觉与文案

- 首屏优先使用真实产物。流程图说明输入、扫描引擎和输出关系；不要只放产品 Logo。
- 流程、架构、状态机描述默认画成 SVG 图片：文本格式可随代码一起版本管理；首屏放“输入 → 引擎 → 输出 + 核心原则”总览图，流程章节放带产物、风险分支和回路的阶段图。
- 图示内容与正文同源验证：技能名、命令、产物名、状态语义必须来自实际代码或运行结果，不在图里写未验证内容。
- 图片之后紧跟文字解释：逐条说明图中阶段、产物和异常路径，不让读者自己猜图例含义。
- SVG 使用系统通用中文字体（如 Microsoft YaHei、PingFang SC），控制文字长度避免溢出；交付前渲染成位图检查截断与重叠。
- GUI GIF 应按用户动作分帧，例如：添加路径 → 执行 → 等待完成 → 展示报告。
- 终端截图要显示执行命令、摘要、报告路径和退出码；风险行用红色强化。
- HTML 报告截图要展示总体结论；异常详情图要展示最深调用路径与可定位的高耗栈/溢出边界函数。
- 对 `FAIL` 等明确风险使用红色文字和整行高亮；说明红色的语义。黄色等次级高亮必须有文字解释。
- 图片要与代码版本同步。产品名、入口文件名、报告标题变更后，重新生成或更新截图、GIF 和 SVG 图示。

### 4. 写出可行动的异常说明

- `FAIL`：说明工具已完成分析、但发现明确风险；给出报告中应查看的字段和复扫动作。
- `WARNING`：说明接近阈值，建议关注趋势。
- `REVIEW`：说明它不等于失败或溢出，而是静态分析无法完全确认调用路径或数据；列出常见原因和人工复核方式。
- `IGNORED`：说明其原始结论仍可查看，但未纳入最终门禁判定。
- 退出码必须单列，明确风险退出码不等于工具运行错误。

### 5. 验证并交付

至少完成：

- 验证 Markdown 为 UTF-8、围栏成对、图片路径存在。
- SVG 图示：XML 合法，渲染为位图后检查文字无截断、元素无重叠、箭头连接正确。
- 实际运行一次主入口，记录真实输出或预期风险退出码。
- 检查报告标题、GUI 标题、脚本名和 README 中的产品名一致。
- 视觉检查首屏、GIF 首帧/帧数、报告风险高亮和命令行图片。
- 简短交付：说明用户最关心的文档变化、验证结果及未覆盖范围。
