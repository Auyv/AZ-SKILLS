# AZ 工作流创建器

将经过验证、具有重复价值的工作步骤固化为可被 Agent 自动发现的工作流技能。

## 适用边界

仅在满足以下条件时创建或更新工作流：任务会重复出现、步骤顺序或安全门禁具有复用价值，且用户明确要求固化或确认应长期复用。

一次性的业务改动、单个缺陷根因、项目专属临时配置或尚未验证的尝试，不创建工作流；保留在任务记录或普通文档中即可。

## 创建位置与命名

1. 定位当前 AZ-SKILLS Git 仓库根目录；不得使用或写入机器相关的绝对路径。
2. 工作流名称必须使用全小写连字符格式 `<name>-workflow`。
3. 在相对路径 `workflow/<name>-workflow/SKILL.md` 创建或更新源码。
4. 目录名、front matter 的 `name`、`manifest.yaml` 中的技能引用必须完全一致；不得与 `skills/` 下已有技能重名。

## 创建流程

1. 读取当前环境的全局规则、AZ-SKILLS 的 `AGENTS.md` 和待参考的现有技能。
2. 提取触发语句、前置条件、可重复步骤、停止条件、权限边界与可观察的验证结果；删除仅属于单次任务的细节。
3. 使用简洁的 YAML front matter：`name`、`description`、`version`。`description` 必须说明何时触发并避免泛化匹配。
4. 在 Markdown 正文中写明输入、步骤、验证、停止条件和交付信息。工作流涉及分支或远端时，必须引用当前全局 Git 门禁：独立分支、MR、不得直接修改目标分支。
5. 在需要使用该工作流的 Agent 目标中更新 `manifest.yaml`；保持无关目标的原有清单不变。
6. 运行 `python sync_skills.py --skill <name>-workflow --dry-run`，检查同步目标与源路径；再运行适用的结构检查和 `git diff --check`。

## 维护与发布

- 修改既有工作流前，先读取完整 `SKILL.md`、清单引用及调用方；优先做窄而有效的修正。
- 使用独立任务分支提交并推送源码，再创建指向目标分支的 MR。不得直接向目标分支推送、快进或合并。
- 未经用户明确要求，不执行正式同步到 Agent 目录；干运行仅用于验证。

## 停止条件

当复用价值不足、命名或目标 Agent 不明确、工作流与普通技能重名、仓库工作区含可能被覆盖的无关修改，或没有用户授权创建/更新时，停止并说明所需决定。
