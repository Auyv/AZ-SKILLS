# Keil 图形配置头文件

生成用户可在 Keil 的 **Configuration Wizard** 页签编辑的配置头。以兼容旧版 uVision、保留产品默认行为和可解释的编译校验为目标。

## 先确定范围

1. 读取目标工程规则，检查 Git 状态、源文件编码和换行。先备份未跟踪、已有未提交修改的文件。
2. 从现有代码整理宏、引用位置、默认值、单位、有效模式、上下限、依赖及对 RAM/时延的影响。宏名优先表达用途，不把处理器角色命名为帧类型开关。
3. 区分三类内容：用户配置；协议固定值；自动推导值。只有用户配置出现在向导中，后两类留在向导结束标记之后。
4. 多工程同步时，分别记录各工程默认值，不把产品差异强制统一。只在范围、默认值或依赖无法从上下文确定时提问。
5. 说明预计修改的头文件、引用源文件、工程文件和检查脚本。未要求迁移宏时，仅添加配置向导注释，不扩展业务改动。

## 编码与兼容规则

- 面向旧版中文 Windows Keil，新生成的中文配置头默认使用 **GBK、无 BOM**。技能 Markdown/Python 资源自身使用 UTF-8；[模板](assets/config_header.h)自身使用 GBK。
- 修改已有文件时先识别编码。已有 UTF-8 文件只有在目标 Keil 已验证可正确显示时才继续用 UTF-8；需要转码时说明原因，严格解码/编码并验证往返一致，禁止 `errors="ignore"` 或 `errors="replace"`。
- 保留目标工程换行习惯。配套脚本必须用配置头的实际编码读写，不能转回 UTF-8 后就声称验证了 GBK 文件。
- 使用已验证的基础标签：`<h>` / `</h>` 分组、`<i>` 提示、`<q>` 布尔开关、`<q.0>` 等位复选框、`<o>` 数值/下拉选项、`<1-1000>` 数值范围、`<0=>` 数字枚举项。
- 默认不用 `<o MACRO_NAME>` 或 `<ROLE_MCU=>` 等标识符扩展。在实测旧版 uVision 中，这会报 `Syntax error in Options Block ... identifier 'RTE' unexpected`。需要具名常量时保留在内部校验和代码比较中，用户配置值使用数字，界面显示 MCU/MPU 等语义名称。
- 开始标记必须在前 100 行，使用 `// <<< Use Configuration Wizard in Context Menu >>>`；显式结束标记使用 `// <<< end of configuration section >>>`。
- 标签写在 `//` 注释中；标签行的说明不要再使用额外的尖括号。依赖说明中的大小关系写“至少”“不超过”，避免混入运算符标签。

## 生成或迁移

以 [assets/config_header.h](assets/config_header.h) 为结构参考，按目标模块替换文件名、保护宏、配置前缀、字段和约束，不照抄示例默认值。

1. 文件头说明：模块用途、上下行方向（适用时）、编码、修改后需重编，以及打开向导的方法。
2. 按用途分组，例如模式、通道、队列、上行聚合、下行预算。每个选项增加 `<i>`，说明单位、有效模式、关键依赖和调大/调小的后果。
3. 向导默认修改注释后遇到的数值。让每个控件紧贴对应 `#define`；同一掩码的多个 `<q.n>` 可以连续放在同一个宏之前，避免中间夹入其他数值定义。
4. 可编辑宏使用单一十进制或十六进制数值，允许外层括号。不要把别名宏、算式或字符串当作数值控件目标；例如可编辑容量写 `(3000)`，上限仍由内部协议常量校验。
5. 角色/模式下拉框使用数值枚举：

   ```c
   // <o> 处理器角色
   // <0=> MCU：连接本地外设
   // <1=> MPU：使用远端外设
   // <i> 表示处理器角色，与报文帧类型无关。
   #define APP_PROCESSOR_ROLE (0)
   ```

6. 避免为了灰显选项而随意使用代码注释开关或删除宏。基础向导不能实现任意依赖联动；通过生效条件提示和编译校验约束组合。
7. 向导外放角色常量、协议常量、派生长度/记录数和 `#if / #error`：检查开关、枚举、上下限、所需功能、缓存最小可容纳对象、字段位宽等真实约束。
8. 不把建议写成硬约束。例如“单次处理预算通常大于一块”不等于必须如此；先看实现是否支持分次处理。协议上限不能只在一端扩大；未初始化的外设/队列不会因增大宏自动启用。
9. 迁移分散宏时，移除重复定义，让原头文件包含新配置头，逐处更新引用；必要时最小修改 `.uvprojx` 注册配置头和 include 路径，保留原 XML 编码。

## 验证与交付

1. 运行随附的只读基础检查器，无第三方依赖：

   ```text
   python <技能目录>/scripts/check_config_header.py <目标配置头>
   ```

   默认按 GBK 检查；只有已验证的 UTF-8 工程使用 `--encoding utf-8`。检查器只接受本技能的保守标签子集，检查标记、分组、数值目标、范围、枚举和基本布尔值；它不是 Keil 的解析器，也不会验证业务依赖。

2. 迁移已有配置时，对比修改前后有效宏值和条件分支，尤其是各产品不同的掩码、队列和缓存。用预处理结果或静态断言验证，不能只比较宏文本。
3. 使用项目现有检查覆盖正常组合及关键非法组合。若运行 Keil 编译，调用 `az-keil-build`，确认新日志和产物，报告实际警告/错误数；不自动烧录。
4. 图形验收与编译分别报告：Keil 打开头文件并切换配置向导，确认中文、选项和值正确；修改代表性的复选框、位掩码、下拉框和数值，再查看 Text Editor 确认改到了正确宏，验证后还原测试值。只有有可用的 UI 能力时直接操作，否则明确说明界面待用户确认。
5. `0 Error(s), 0 Warning(s)` 不能证明向导语法和中文显示正确。遇到外部修改提示，重新加载文件后再检查，不用旧编辑缓存下结论。
6. 交付实际文件路径、默认值是否保持、验证层级、限制及备份/回滚位置。未经授权不 commit、push、发布或同步技能。

## 已验证的故障边界

| 现象 | 优先检查与处理 |
| --- | --- |
| `Options Block` 指向 `<o RTE_...>`，提示标识符 unexpected | 改成 `<o>`、数字枚举和数值宏；不只改枚举项文字 |
| 向导打开，但“模式选择”显示成“妯″紡閫夋嫨” | UTF-8 被当作 GBK；严格转成 GBK，并同步检查脚本编码，重新加载 |
| 界面修改影响到另一个参数 | 检查注释到目标宏之间是否夹入了其他值、表达式或不兼容的标识符引用 |
| 缓存增大后通信失败 | 核对协议、对端、长度字段及 RAM 上限，保留跨宏校验；不能只扩大本端容量 |

这些边界来自实际旧版 Keil 配置头案例。不要据此声称所有 uVision 版本都不支持 UTF-8 或标识符标签。

官方基础语法参考：[Keil Configuration Wizard](https://www.keil.com/support/man/docs/uv4cl/uv4cl_ut_configwizard.htm)。当前工程可实测的版本兼容性优先于较新规范的扩展标签。
