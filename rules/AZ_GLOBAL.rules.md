# 全局规则

## 基础规则

- 优先使用中文回答
- AI 思考过程和无指定路径的临时文件默认放在 `./.ai_tmp/`
- 保持简洁，总结控制在必要范围
- 避免无信息的客套语
- 修改文件、运行命令前先用一句话说明打算做什么

## 工具使用

- 修改已有文件前先识别编码（UTF-8/GB2312/GBK），谨防乱码
- 引用代码位置用 `file_path:line_number` 形式，便于点击跳转

## Go 工具开发

- 识别到用户在开发 Go 命令行工具（新建或迭代 CLI 类项目）时，主动询问是否需要为其增加 GUI 图形界面，再开始实施
- 用户确认需要 GUI 时，默认推荐技术栈：Wails V2（稳定版）+ Vue3 + TypeScript；打包产物不得开启 HTTP 服务、不得监听本地 TCP 端口
- Go GUI 的业务逻辑保留在 Go 后端协程执行并复用既有 CLI 逻辑；前端通过 Wails 绑定调用导出函数，长任务日志/状态用 runtime.EventsEmit 推送、EventsOn 接收，禁止前端轮询

## 编码习惯

- C 语言编码遵循 [C 语言编码规范](./c_code.rules.md)。
- 优先修改已有文件，不无谓新建。但需要在 `./.ai_tmp/bak/` 中做好备份，防止无法回退。
- 日志信息优先 ASCII 字符 + GB2312 中文，防止显示异常。
- 注释内容优先使用 中文。

## 输出与反馈

- 不可逆操作（删除/覆盖/格式化/清库）前先 Read 目标并说明影响
- 多文件改动时先列清单再动手
- 能用合理默认值解决的直接做并简短说明，不打断用户
- 工具报错要把原始信息原样呈现，不包装、不美化

## Markdown 与 Mermaid

- 生成或修改 Markdown 文档时，Mermaid 图必须兼容 Mermaid 10.1.0，避免使用仅在更高版本支持的语法。
- Mermaid `flowchart` 的边标签统一使用双引号包裹，写成 `A -->|"中文标签"| B`；中文、空格、斜杠、标点或其他特殊字符不得直接写成未加引号的边标签。
- Mermaid 节点文本包含中文、空格、路径、斜杠、括号或 HTML 换行时，使用 `NODE["节点文本<br/>第二行"]` 形式。
- 交付包含 Mermaid 的 Markdown 前，必须检查 Mermaid 代码围栏成对，并检查所有 `-->|...|`、`--|...|`、`-.->|...|`、`<-->|...|` 边标签均已使用双引号；条件允许时使用目标渲染器或兼容版本实际渲染验证。
- Mermaid 渲染失败时，应保留原始错误信息，按错误行定位语法问题，不以截图正常或其他渲染器可用代替目标版本验证。

## 工作流

- 没有明确同意不执行：git commit / push / 强制推送 / reset --hard
- 不主动安装新依赖或运行破坏性命令
- 遇到错误先排查根因，禁止用 `--no-verify` 等绕过手段
- 同一问题连续 3 次修复失败时主动更换解决思路，并向用户发起澄清问题
- 每次计划编写完成后，必须向用户明确告知计划存放绝对路径并在对话中总结计划要点，便于用户审核并决定是否批准
