# Git 操作规则

本规则适用于创建、切换、合并、提交、推送、重置或管理 Git 分支的任务。

## 授权与安全

- 未获明确同意不得执行 `git commit`、`git push`、强制推送或 `git reset --hard`。

## 分支命名

- AI 创建的个人任务分支采用语义格式 `<name>-<tag>-<date>@<from>`；文档中的 `tag[date]` 仅表示任务标签后追加日期，实际 Git 分支名不得使用方括号。
- `name` 固定为 `jpz_ai` 或 `jpz_codex`；`tag` 使用 lowerCamelCase（小驼峰）；`date` 使用 `YYMMDD`；`from` 为分叉来源分支。
- 示例：`jpz_ai-configDefaultPropMr2-260917@qzf_20260908`。

## 分支复用

- 开始修改前先检查当前分支。若当前分支已符合 AI 分支命名格式，即以 `jpz_ai-` 或 `jpz_codex-` 开头并包含 `@<from>` 后缀，则直接复用当前分支，不得为同一任务重复创建新的 AI 分支。
- 仅当当前分支不是 AI 分支时，才从实际来源分支 `<from>` 创建新的 AI 任务分支。

## 创建 MR 前同步

- AI 分支向远端 `<from>` 分支创建或更新 MR 前，必须先拉取并同步远端 `<from>` 的最新提交。
- 推荐流程：确认工作区干净，切换到本地 `<from>`，执行仅快进拉取以同步 `origin/<from>`；再切回 AI 分支，将最新 `<from>` 合入 AI 分支并确认不存在冲突；随后推送 AI 分支并创建或更新以 `<from>` 为目标分支的 MR。
- 若同步或合入 `<from>` 时出现冲突，必须先解决并完成必要验证，不得在冲突未解决或未确认兼容性的情况下创建 MR。

## MR 合并后清理

- 只有在远端明确确认对应 MR 已合并后，才可清理本地 AI 分支；MR 仍处于打开、关闭未合并或状态不明时不得删除。
- 确认 MR 已合并且工作区干净后，切换回该 AI 分支名中 `@` 后记录的 `<from>` 分支，拉取并同步 `origin/<from>`，再使用安全删除方式删除本地对应的 AI 分支。
- 默认只删除本地 AI 分支，不删除远端分支；如需删除远端 AI 分支，必须另行获得用户明确授权。
